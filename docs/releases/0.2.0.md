# The Post 0.2.0 — «Пилот: почта, календари, контакты, правила»

Первый выпуск с номером версии после ночных бет `beta-*`. Для пилота в небольшой организации на одном сервере: к
почте добавились календари, контакты, встречи, правила Sieve с автоответом, веб-консоль администратора и защита от
перебора паролей по адресу клиента.

## Что нового

### Календари и контакты

- **CalDAV** — календари и задачи: дом календарей, `calendar-query`, `multiget`, `sync-collection`, повторяющиеся
  события, оповещения по умолчанию. Клиенты — Thunderbird, iOS и macOS, DAVx5, Evolution.
- **CardDAV** — адресные книги, vCard 3 и 4, поиск контактов по имени и адресу по индексу; адресная книга
  организации (сотрудники и группы рассылки из каталога).
- **В узле** — роль `dav`; по умолчанию на том же слушателе, что JMAP (порт 443, путь `/dav/`), автонастройка через
  `/.well-known/caldav` и `/.well-known/carddav`. Отдельный порт — `http.dav`.
- **JMAP Calendars и Contacts** — `Calendar`, `CalendarEvent` с развёрткой повторов, `AddressBook`, `ContactCard`
  (по текущему черновику IETF).
- **Встречи** — планирование по RFC 6638 (iTIP): приглашения, ответы, отмены, входящие расписания; адрес участника —
  основной адрес учётной записи или любой её псевдоним. Обмен приглашениями по почте с внешними участниками (iMIP);
  занятость участников (free/busy), для повторяющихся событий — тоже. В JMAP — `Principal`, `ParticipantIdentity`,
  `sendSchedulingMessages`, `CalendarEventNotification`.
- **Приглашение из почтового клиента** — письмо-приглашение, отправленное коллеге по SMTP (587/465) со своего адреса
  или псевдонима, попадает и в его календарь, а не только во «Входящие».
- **Обслуживание** — роль `maintenance` чистит надгробия DAV и журнал автоответов по сроку.

### Правила и автоответ

- **Свой интерпретатор Sieve** — разбор, проверка, выполнение; `fileinto`, `redirect`, `reject`, `body`, `vacation` и
  другие расширения; пределы размера и шагов — секция `sieve`.
- **Правила при доставке** — скрипт организации, затем скрипт пользователя. Пересланное правилом письмо и
  внутренний автоответ доставляются как обычное письмо, через правила получателя; петля обнаруживается, письмо
  остаётся во «Входящих».
- **Автоответ** — не чаще 60 в час на ящик, журнал ответов — 90 суток.
- **ManageSieve** (RFC 5804, порт 4190, STARTTLS) — в роли `imap`, служба SASL `sieve`; включён в эталонах Ansible,
  Docker Compose и Helm.
- **Правка правил** — JMAP `SieveScript` и `VacationResponse`, ManageSieve, Admin API, веб-консоль,
  `thepost admin sieve list|get|put|activate|deactivate|delete`; администратор правит правила пользователя с записью в
  журнал аудита.

### Администрирование

- **Веб-консоль** — организация и политика, домены, учётные записи и пароли приложений, группы рассылки и модерация,
  правила и автоответ, транспорт (принятые домены, источники, маршруты), корзина, журналы доставки и аудита.
  Вход — токеном `thepost admin init` или через OIDC. Встроена в бинарный файл выпуска и в образ Docker, раздаётся
  ролью `admin` по адресу Admin API: `https://127.0.0.1:8443/console/` (снаружи — через SSH-туннель). Выключить —
  `admin.console.enabled: false`. Консоль можно раздавать и своим веб-сервером: адреса страниц консоли —
  `admin.console.cors_origins`; настройки входа OIDC консоль берёт из `GET /api/v1/session`.
- **Политики организации действуют в узле** — цепочка «организация → домен → учётная запись»; лимиты `max_recipients`
  (по умолчанию 100 получателей в письме), `send_per_hour` (1000 писем в час), `rcpts_per_hour` (2000 получателей в
  час — главная защита от рассылки со взломанного ящика), селектор DKIM `dkim_selector`, набор фильтров
  `milter_profile`. Изменение политики применяется к следующему сеансу без перезапуска. Лимиты одни для отправки по
  SMTP и JMAP, в том числе для отложенной отправки: письмо учитывается при постановке.
- **Отложенная отправка и отмена** — JMAP `EmailSubmission` с `sendAt` (до 30 суток вперёд, `jmap.submission.max_delayed_send`)
  и отменой до выпуска; статус доставки — из журнала доставки.
- **Журнал аудита в базе** — все действия администраторов в таблице `audit_log`, `GET …/audit` и консоль. Выгрузка в
  SIEM — syslog (RFC 5424 поверх TLS с проверкой сертификата) и OTLP: секция `admin.audit`, выгрузку ведёт роль
  `maintenance`; пока приёмник недоступен, записи ждут в базе и уходят по порядку, без пропусков и повторов.
- **Аудит доступа к чужим ящикам** — политика аудита организации и ящика; отправка от чужого адреса, удаление, перенос,
  изменение правил владельца пишутся в журнал, выборка — Admin API (роль аудитора).
- **Admin API для соответствия Exchange** — почтовые контакты организации, дерево подразделений и учётные записи
  подразделения, фильтр динамической группы, списки надёжных и заблокированных отправителей ящика, отключённые ящики
  (список, восстановление, подключение к другой учётной записи), подтверждение синхронизации каталога сверх порога
  удаления. Все маршруты работают на PostgreSQL, без ответов 503.
- **Блокировка учётной записи** закрывает её открытые сеансы IMAP и POP3 сразу, в том числе в `IDLE`; новый вход
  отклоняется во всех протоколах.
- **Модерация групп** — одобрение и отказ работают (раньше были ответы 500).
- **Корзина** — тема и отправитель скрытых писем видны администратору без их восстановления.
- **Один API доменов** — `/api/v1/orgs/{org}/transport/domains` (консоль и CLI — на нём же).
- **`thepost admin`** — постраничный список учётных записей (`--after`), блокировка учётной записи, правила и
  автоответ, скрипт организации; вход администратора через OIDC с устройства (RFC 8628);
  `thepost admin openapi` — схема Admin API без запуска узла.
- **Каталог LDAP** — участники групп сопоставляются по `external_id`; признак скрытия учётной записи из адресной книги
  читается из `msExchHideFromAddressLists` (настройка `accounts.hidden`).
- **`thepost doctor`** — кодировка и `LC_CTYPE` базы, сроки внутренних сертификатов, все ключи DKIM домена, ключ TLS
  из OpenBao, приёмники выгрузки аудита; DNS для календарей и контактов — записи SRV `_caldavs._tcp`,
  `_carddavs._tcp` и TXT `path=` с готовыми строками для зоны.

### Почта и защита

- **Защита от перебора паролей по адресу клиента** — во всех протоколах входа: SMTP, IMAP и POP3, JMAP, ManageSieve,
  CalDAV и CardDAV. Неудачи засчитываются и учётной записи, и адресу и подсети клиента, в том числе под
  несуществующими именами входа. За L4-балансировщиком с PROXY protocol v2 (слушатели SMTP, IMAP, POP3, ManageSieve —
  `proxy_protocol`, `trusted_proxies`) учитывается настоящий адрес клиента из заголовка.
- **Доверенные подсети** — `ratelimit.trusted: [CIDR]`: предел частоты соединений к ним не применяется, защита от
  перебора действует. Секция `ratelimit` применяется без перезапуска.
- **Ключи TLS из OpenBao** — слушатели клиентов, LDAP, OIDC, syslog аудита: ключ только секретом
  `tls.key: { secret: … }`, файлов ключа на диске нет. Ключ межузлового канала перечитывается без перезапуска.
- **Встроенный ACME** — публичный сертификат (например, Let's Encrypt) узел выпускает и продлевает сам (проверка
  HTTP-01 на порту 80), ключ кладёт в OpenBao; certbot больше не нужен.
- **Подписанный профиль `.mobileconfig`** — автонастройка iPhone и Mac без «Не проверен» (подпись сертификатом TLS
  сервера).
- **Доверенные источники, SRS и ARC** — пересылка без поломки SPF и DMARC; источник опознаётся по адресу или по
  сертификату клиента (mTLS), с проверкой списков отзыва (CRL).
- **Milter по направлениям** — фильтры для входящей почты (антиспам, антивирус) и для исходящей (submission и JMAP
  `EmailSubmission`, например DLP), у каждого своя политика при недоступности.

### Установка и эксплуатация

- **Любой процессор x86-64** — сервер собирается под базовый x86-64 без AVX2: работает на старых и виртуальных
  процессорах; каждая сборка проверяется запуском на эмуляции старого процессора.
- **Одна конфигурация SMB** — `deploy/config/all.yaml`; Ansible и Docker Compose подставляют в неё только значения
  установки (таблица — в `deploy/README.md`).
- **Порты ниже 1024 — через сокеты systemd**: служба работает без root и без capabilities.
- **Образ в ghcr.io** — закрытый; Helm требует `imagePullSecrets`, Compose — `docker login ghcr.io`. Тег образа —
  версия выпуска (`appVersion` чарта), установка закреплена за выпуском.
- **ОС эталона Ansible** — Debian 13 (основа) и 12, Ubuntu 26.04 и 24.04, Astra Linux SE 1.8, РЕД ОС 8, AlmaLinux 10 и
  9 (совместимость с RHEL 9 и 10). Тонкости — [требования к окружению](../PREREQUISITES.md#известные-тонкости).
- **Резервное копирование** — плейбук включает сам: база — pgBackRest (WAL непрерывно, восстановление на любой
  момент за `thepost_backup_retention_days`, по умолчанию 7 суток), каталог писем — restic или rsync раз в час,
  секреты — снимок Raft OpenBao; копии — в каталоге, на отдельном томе или в S3; `restore.yml` — и на семействе RHEL.
  [Как восстановить](../INSTALL.md#восстановление), в том числе [на новом сервере](../INSTALL.md#новый-сервер-вместо-потерянного).
- **Эталон** — UTC и chrony, база в UTF-8, перевыпуск внутренних сертификатов при повторном прогоне; режим «не ждать
  готовности узла».
- **Надёжный старт** — при медленном OpenBao узел повторяет вход с растущей паузой; systemd перезапускает службу с
  паузой от 10 с до 5 мин.
- **Обслуживание** — `thepost verify` по расписанию в роли `maintenance`, очистка журнала доставки, отправок и
  токенов `admin init` по сроку.
- **Метрики** — пул соединений с СУБД, слушатель сигналов, доля NOTIFY, «сироты» после сборки мусора, отказы по
  лимитам отправки — в `/metrics`.

## Несовместимые изменения для администратора

Старые ключи не принимаются: `thepost config check` и запуск узла останавливаются с ошибкой разбора. Старый путь
рядом с новым не оставляется.

| Было | Стало |
|---|---|
| `smtp.delivery.local_domains` | Удалён. Локальные домены — принятые домены организации в базе: `thepost admin domain …`, консоль «Домены» |
| `smtp.dkim.domains.<домен>.selector` | Удалён. Селектор — `dkim_selector` политики организации, домена или ящика; не задан — письмо подписывается всеми ключами домена из `keys` |
| `smtp.limits.max_recipients`, `smtp.limits.messages_per_hour`, `smtp.limits.recipients_per_hour` | Удалены. Лимиты — поля политики `max_recipients`, `send_per_hour`, `rcpts_per_hour` |
| Фильтр Milter: `inbound: true`, `submission: true` | `direction: inbound` или `direction: outbound`; фильтр для обоих направлений описывается дважды. `on_failure` по умолчанию: входящая — `accept`, исходящая — `tempfail`. Наборы фильтров — `smtp.milter.profiles`, выбор — `milter_profile` политики |
| Неудачные `AUTH` в SMTP блокировали адрес клиента (`ratelimit.block_duration`) | После `smtp.limits.max_auth_failures` неудач соединение закрывается; перебор пароля блокирует `auth.abuse` — по учётной записи и по адресу клиента |
| Admin API `/api/v1/orgs/{org}/domains` | Удалён: `/api/v1/orgs/{org}/transport/domains`, политика домена — `…/transport/domains/{id}/policy` |
| `tls.key_file` у слушателей (секция `tls`), в `auth.ldap`, `auth.oidc` и `admin.audit.syslog` | Удалён: только `tls.key: { secret: "<путь>#<поле>" }` из OpenBao; ключ слушателей по умолчанию — `thepost/tls#key`. У межузлового канала и клиентского сертификата PostgreSQL `key_file` пока принимается |
| `admin.oidc.issuer` | Удалён: издатель — `auth.oidc.issuer`, в `admin.oidc` остаются `client_id` и `scope`; `admin.oidc` без `auth.oidc` — ошибка запуска роли `admin` |
| `admin.audit.syslog.queue`, `admin.audit.syslog.retry` | Удалены: записи ждут выгрузки в базе; паузы и размер пачки — `admin.audit.interval`, `admin.audit.retry`, `admin.audit.batch` |
| Ansible: `thepost_tls_mode: certbot` | Удалён: `acme` (по умолчанию, встроенный ACME) или свои файлы сертификата; ключ — в OpenBao |
| Ansible: `thepost_socket_activation`, CAP_NET_BIND_SERVICE (`bind-capability.conf`) | Удалены: порты ниже 1024 — всегда сокеты systemd |
| Ansible: `thepost_listen_address`; Compose: `compose/thepost-smb.yaml` | Удалены: конфигурация — пресет `deploy/config/all.yaml` и значения установки (инвентарь, переменные `THEPOST_*`) |

## Как обновиться

- **С бет `beta-*` — только новая установка.** Перенос данных и настроек с бет не поддерживается: поставьте 0.2.0 на
  чистую ВМ или с новой базой и каталогом писем по [инструкции](../INSTALL.md) и заведите учётные записи заново.
  Свои `config.yaml` и инвентарь сверьте с таблицей выше.
- База PostgreSQL — в кодировке UTF8 с `LC_CTYPE` UTF-8; иначе — [пересоздать базу](../PREREQUISITES.md#пересоздать-базу-в-utf-8).
- Дальнейшие выпуски 0.2.x — повтором плейбука, `helm upgrade` или новым образом Compose; миграции базы применяются
  автоматически при запуске узла ([обновление](../INSTALL.md#обновление)). Перед обновлением рабочего сервера —
  внеочередная копия `sudo systemctl start thepost-backup@full`.
- Контакты CardDAV, сохранённые до 0.2.0, находятся поиском по имени и адресу после первой правки карточки
  клиентом; остальные операции с ними работают как обычно.

## Известные ограничения

- **Один сервер.** Enterprise — шарды и реплики СУБД, отказоустойчивость, несколько узлов за балансировщиком,
  S3 для писем, режим edge без базы данных — в следующих этапах.
- **Встречи с внешними участниками и публикация занятости**: приглашения внешним участникам ходят по почте (iMIP), но
  публикации календаря и занятости наружу (ICS, free/busy для внешних) нет.
- **Общий доступ к календарям и книгам, представители и ресурсы** (переговорные) — не входят в 0.2.0.
- **Скрытие из адресной книги организации** — признак `msExchHideFromAddressLists` читается из LDAP, но скрытые
  учётные записи пока видны в книге «Организация»; скрытые группы рассылки не показываются.
- **Каталог по расписанию**: контакты, оргструктура и отключение ящиков из LDAP пока не синхронизируются
  автоматически — каталог используется для входа, групп и адресной книги; контакты и подразделения заводятся через
  Admin API.
- **Списки отправителей и динамические группы** хранятся и правятся через Admin API, но при доставке пока не
  применяются; в JMAP их нет.
- **Блокировка учётной записи** закрывает сеансы IMAP и POP3; сеансы ManageSieve и SMTP submission доживают до
  разрыва (новый вход отклоняется).
- **Приглашение из почтового клиента** попадает в календарь коллеги, только если отправлено со своего адреса или
  псевдонима; от имени другого (Send As, Send on Behalf) — остаётся письмом.
- **Архив ящика** и выгрузка отключённого ящика — нет.
- **Встроенный ACME** на стенде с публичным именем ещё не проверялся: эталон проверен с сертификатом внутреннего
  УЦ (`thepost_tls_mode: internal`).
- **Испытания нагрузки** (приложение Д.6) не проведены; выпуск они не блокируют — по решению владельца.
- **ОС**: на Astra Linux SE 1.8 эталон рассчитан на выключенную ЗПС, копия писем — rsync без шифрования (защита
  хранилища копий — [отдельно](../PREREQUISITES.md#astra-linux-se-и-ред-ос-копии-и-антивирус)), ClamAV нет; на РЕД ОС 8
  ClamAV нет, бинарный файл — с управляющей машины (`thepost_binary_src`); AlmaLinux 10 — процессор x86-64-v3 (требование
  самой ОС); работа с PARSEC на Astra и SELinux в `enforcing` — проверяются на ВМ.
