## Что нового

### Календари и контакты

- **CalDAV** — календари и задачи: дом календарей, `calendar-query`, `multiget`, `sync-collection`, повторяющиеся
  события. Клиенты — Thunderbird, iOS и macOS, DAVx5, Evolution.
- **CardDAV** — адресные книги, vCard 3 и 4, адресная книга организации (сотрудники из каталога).
- **В узле** — роль `dav`; по умолчанию на том же слушателе, что JMAP (порт 443, путь `/dav/`), автонастройка через
  `/.well-known/caldav` и `/.well-known/carddav`. Отдельный порт — `http.dav`.
- **JMAP Calendars и Contacts** — `Calendar`, `CalendarEvent` с развёрткой повторов, `AddressBook`, `ContactCard`
  (по текущему черновику IETF, решение 35).
- **Встречи** — планирование по RFC 6638 (iTIP): приглашения, ответы, отмены, входящие расписания; обмен
  приглашениями по почте с внешними участниками (iMIP); занятость участников (free/busy), для повторяющихся событий —
  по запросу. В JMAP — `Principal`, `ParticipantIdentity`, `sendSchedulingMessages`, `CalendarEventNotification`.
- **Обслуживание** — роль `maintenance` чистит надгробия DAV и журнал автоответов по сроку.

### Правила и автоответ

- **Свой интерпретатор Sieve** — разбор, проверка, выполнение; `fileinto`, `redirect`, `reject`, `body`, `vacation` и
  другие расширения; пределы размера и шагов — секция `sieve`, одни и те же во всех каналах проверки.
- **Правила при доставке** — скрипт организации, затем скрипт пользователя. Пересланное правилом письмо и
  внутренний автоответ доставляются как обычное письмо, через правила получателя; петля обнаруживается, письмо
  остаётся во «Входящих» (решение 61).
- **Автоответ** — не чаще 60 в час на ящик, журнал ответов — 90 суток (решение 60).
- **ManageSieve** (RFC 5804) в роли `imap`, служба SASL `sieve`.
- **Правка правил** — JMAP `SieveScript` и `VacationResponse`, Admin API, веб-консоль, `thepost admin sieve
  list|get|put|activate|deactivate|delete`; администратор правит правила пользователя с записью в журнал аудита.

### Администрирование

- **Веб-консоль** — организация и политика, домены, учётные записи и пароли приложений, группы рассылки и модерация,
  правила и автоответ, транспорт (принятые домены, источники, маршруты), корзина, журналы доставки и аудита.
  Вход — токеном `thepost admin init` или через OIDC. Встроена в бинарный файл выпуска и раздаётся ролью `admin` по
  адресу Admin API: `https://127.0.0.1:8443/console/` (снаружи — через SSH-туннель). Выключить —
  `admin.console.enabled: false`.
- **Модерация групп** — одобрение и отказ работают (были ответы 500, FIX-01, FIX-02).
- **Журнал аудита в базе** — таблица `audit_log`, `GET …/audit` отдаёт записи (раньше — 503).
- **Политики организации через Admin API** — цепочка «организация → домен → учётная запись»; новые поля
  `max_recipients`, `send_per_hour`, `rcpts_per_hour`, `dkim_selector`, `milter_profile`.
- **Один API доменов** — `/api/v1/orgs/{org}/transport/domains` (консоль и CLI — на нём же).
- **`thepost admin`** — постраничный список учётных записей (`--after`), блокировка учётной записи, правила и
  автоответ, скрипт организации; вход администратора через OIDC с устройства (RFC 8628);
  `thepost admin openapi` — схема Admin API без запуска узла.
- **Каталог LDAP** — участники групп сопоставляются по `external_id`.
- **`thepost doctor`** — кодировка и `LC_CTYPE` базы, сроки внутренних сертификатов, все ключи DKIM домена, ключ TLS
  из OpenBao.

### Почта и защита

- **Подписанный профиль `.mobileconfig`** — автонастройка iPhone и Mac без «Не проверен» (подпись сертификатом TLS
  сервера).
- **Доверенные источники, SRS и ARC** — пересылка без поломки SPF и DMARC; источник опознаётся по адресу или по
  сертификату клиента (mTLS), с проверкой списков отзыва (CRL).
- **Milter по направлениям** — фильтры для входящей почты (антиспам, антивирус) и для исходящей (submission и JMAP
  `EmailSubmission`, например DLP), у каждого своя политика при недоступности.
- **Доверенные подсети** — `ratelimit.trusted: [CIDR]`: предел частоты соединений к ним не применяется, защита от
  перебора действует.
- **Ключи TLS из OpenBao** — слушатели клиентов, межузловой канал, PostgreSQL, LDAP, OIDC, syslog аудита; ключ
  межузлового канала перечитывается без перезапуска; встроенный ACME кладёт выпущенный ключ в OpenBao.

### Установка и эксплуатация

- **ОС эталона Ansible** — Debian 13 (основа) и 12, Ubuntu 26.04 и 24.04, Astra Linux SE 1.8, РЕД ОС 8, AlmaLinux 10 и
  9 (совместимость с RHEL 9 и 10). Тонкости — [требования к окружению](../PREREQUISITES.md#известные-тонкости).
- **Резервное копирование** — плейбук включает сам: база — pgBackRest (WAL непрерывно, восстановление на любой
  момент за `thepost_backup_retention_days`, по умолчанию 7 суток), каталог писем — restic или rsync раз в час,
  секреты — снимок Raft OpenBao; копии — в каталоге, на отдельном томе или в S3; `restore.yml` — и на семействе RHEL.
  [Как восстановить](../INSTALL.md#восстановление), в том числе [на новом сервере](../INSTALL.md#новый-сервер-вместо-потерянного).
- **Эталон** — UTC и chrony, база в UTF-8, перевыпуск внутренних сертификатов при повторном прогоне; режим «не ждать
  готовности узла».
- **Надёжный старт** — при медленном OpenBao узел повторяет вход с растущей паузой; systemd перезапускает службу с
  паузой от 10 с до 5 мин.
- **Обслуживание** — `thepost verify` по расписанию в роли `maintenance`, очистка журнала доставки и токенов
  `admin init` по сроку.
- **Метрики** — пул соединений с СУБД, слушатель сигналов, доля NOTIFY, «сироты» после сборки мусора — в `/metrics`.

## Несовместимые изменения для администратора

Старые ключи не принимаются: `thepost config check` и запуск узла останавливаются с ошибкой разбора. Старый путь
рядом с новым не оставляется (решение 93).

| Было | Стало |
|---|---|
| `smtp.delivery.local_domains` | Удалён. Локальные домены — принятые домены организации в базе: `thepost admin domain …`, консоль «Домены» (решение 96) |
| `smtp.dkim.domains.<домен>.selector` | Удалён. Селектор — `dkim_selector` политики организации, домена или ящика; не задан — письмо подписывается всеми ключами домена из `keys` (решение 97) |
| `smtp.limits.max_recipients`, `smtp.limits.messages_per_hour`, `smtp.limits.recipients_per_hour` | Удалены. Лимиты — поля политики `max_recipients`, `send_per_hour`, `rcpts_per_hour` (решение 97) |
| Фильтр Milter: `inbound: true`, `submission: true` | `direction: inbound` или `direction: outbound`; фильтр для обоих направлений описывается дважды. `on_failure` по умолчанию: входящая — `accept`, исходящая — `tempfail`. Наборы фильтров — `smtp.milter.profiles`, выбор — `milter_profile` политики |
| Неудачные `AUTH` в SMTP блокировали адрес клиента (`ratelimit.block_duration`) | После `smtp.limits.max_auth_failures` неудач соединение закрывается; перебор пароля учётной записи блокирует `auth.abuse` (решение 99) |
| Admin API `/api/v1/orgs/{org}/domains` | Удалён: `/api/v1/orgs/{org}/transport/domains`, политика домена — `…/transport/domains/{id}/policy` (решение 94) |
| `tls.key_file` в `auth.ldap`, `auth.oidc` и `admin.audit.syslog` | Удалён: только `tls.key: { secret: "<путь>#<поле>" }` из OpenBao (решение 100). У слушателей клиентов, межузлового канала и PostgreSQL `key_file` пока принимается |

## Как обновиться

- **С бет `beta-*` — только новая установка.** Перенос данных и настроек с бет не поддерживается (решение 93):
  поставьте 0.2.0 на чистую ВМ или с новой базой и каталогом писем по [инструкции](../INSTALL.md) и заведите учётные
  записи заново. Свои `config.yaml` и инвентарь сверьте с таблицей выше.
- База PostgreSQL — в кодировке UTF8 с `LC_CTYPE` UTF-8; иначе — [пересоздать базу](../PREREQUISITES.md#пересоздать-базу-в-utf-8)
  (решение 29).
- Дальнейшие выпуски 0.2.x — повтором плейбука, `helm upgrade` или новым образом Compose, миграции базы
  применяются сами ([обновление](../INSTALL.md#обновление)).

## Известные ограничения

- **Защита от перебора — только по учётной записи**: неудачи с несуществующими именами входа адресу клиента пока не
  засчитываются.
- **Политика организации в SMTP узла пока не действует**: лимиты отправки и получателей, селектор DKIM и профиль
  Milter из политики сохраняются через Admin API и консоль, но узел их ещё не применяет и действует по умолчаниям:
  1000 писем в час на учётную запись, 100 получателей в письме, подпись всеми ключами домена, все фильтры своего
  направления.
- **Выгрузка журнала аудита в SIEM** (`admin.audit.syslog`, OTLP) настраивается, но узел её не запускает; журнал —
  в базе, читается через Admin API и консоль.
- **ManageSieve в поставке выключен**: в эталонах нет секции `sieve.managesieve.listen` и порта 4190 — правила
  правятся через JMAP, консоль, Admin API и CLI.
- **Веб-консоль — только во встроенном бинарном файле выпуска**: в образе Docker её пока нет.
- **Не входит в 0.2.0**: общий доступ к календарям и книгам, представители, ресурсы (переговорные), публикация ICS;
  приглашение, отправленное внутренним адресатам из почтового клиента, остаётся письмом; архив ящика, отложенная
  отправка, личные списки отправителей, динамические группы; кластер и Enterprise.
- **ОС**: на Astra Linux SE 1.8 эталон рассчитан на выключенную ЗПС, копия писем — rsync без шифрования (защита
  хранилища копий — [отдельно](../PREREQUISITES.md#astra-linux-se-и-ред-ос-копии-и-антивирус)), ClamAV нет; на РЕД ОС 8
  ClamAV нет, бинарный файл — с управляющей машины (`thepost_binary_src`); AlmaLinux 10 — процессор x86-64-v3; работа
  с PARSEC на Astra и SELinux в `enforcing` — проверяются на ВМ.
