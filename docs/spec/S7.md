# 7. Компоненты и лицензии

## 7.1. Лицензионная политика

- библиотеки, вкомпилированные в бинарный файл: MIT, Apache-2.0, BSD, ISC, MPL-2.0, Zlib, Unicode; copyleft-лицензии (GPL, AGPL, LGPL при статической линковке) не допускаются; контроль — cargo-deny в CI, SBOM в каждом выпуске;
- внешние системы, взаимодействующие с продуктом по сети без линковки, могут иметь любую одобренную OSI лицензию; их выбор — за заказчиком;
- динамически подключаемые системные библиотеки (MIT Kerberos для GSSAPI) — по лицензии библиотеки.

**Обоснование.** Требование юридической чистоты относится к коду продукта; сетевое взаимодействие с внешними системами не создаёт производного произведения.

Библиотеки mail-parser, mail-auth, mail-builder, mail-send, smtp-proto и calcard разработаны проектом Stalwart и распространяются под пермиссивными лицензиями; используются как внешние зависимости. Код сервера Stalwart (AGPL-3.0) не заимствуется; Stalwart используется как эталон в тестах совместимости протоколов.

**Обоснование.** Зрелые библиотеки сокращают объём собственной разработки на 15–20 % и снижают риски корректности в наиболее сложных областях — разборе MIME и криптографической аутентификации почты.
