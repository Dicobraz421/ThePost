# 1. Общие положения

## 1.1. Назначение и границы продукта

The Post — серверная часть корпоративной системы электронной почты и совместной работы класса Modern Enterprise Mail: юридически чистая замена Microsoft Exchange на открытых стандартах (SMTP, IMAP, JMAP, CalDAV, CardDAV) вместо проприетарного стека (MAPI, EWS, ActiveSync).

В базовую поставку входят:

- почтовый транспорт (приём, отправка, очередь) и доступ к почте;
- календари, контакты, транспорт синхронизации задач и заметок;
- серверные правила обработки почты;
- полнотекстовый поиск;
- хранение, дедупликация, корзина;
- интерфейсы администрирования, экспорта и импорта;
- несколько почтовых доменов в одной организации.

Функции сверх базовой поставки реализуются дополнительными модулями (п. 1.3).

В состав продукта не входят и подключаются через стандартные интерфейсы:

- балансировка трафика (п. 6.1);
- антиспам и антивирус (Milter, п. 4.1);
- службы каталогов и поставщики удостоверений (п. 5.1);
- высокая доступность СУБД и объектного хранилища (раздел 3);
- хранение секретов — OpenBao или совместимое с API HashiCorp Vault хранилище заказчика (п. 6.7);
- резервное копирование данных (п. 5.3);
- мониторинг, визуализация, оповещение (п. 6.4);
- файловые хранилища (WebDAV) и бизнес-логика таск-менеджера.

**Обоснование.** Продукт — почтовый сервер, а не платформа «всё в одном». Смежные задачи у заказчиков решены промышленными системами; их встраивание увеличивает объём кода, поверхность атаки и стоимость эксплуатации без выигрыша для назначения продукта.

## 1.2. Профили развёртывания

Продукт поставляется одним бинарным файлом и одним OCI-образом. Профиль определяется конфигурацией (config.yaml) при запуске; отдельных сборок нет.

**Таблица: Профили развёртывания**

| Параметр | SMB | Enterprise-ВМ | Enterprise-K8s |
|---|---|---|---|
| Масштаб | До 1 000 ящиков | От 1 000 ящиков | От 1 000 ящиков, динамическая нагрузка |
| Узлы приложения | 1 ВМ, все роли в одном процессе | N ВМ, роли под systemd | Поды по ролям, HPA |
| Метаданные | PostgreSQL, одиночный экземпляр | Кластер PostgreSQL + PgBouncer | Кластер PostgreSQL + PgBouncer |
| BLOB и индексы | Локальная POSIX-директория | S3 (эталон — SeaweedFS) | S3 (эталон — SeaweedFS) |
| Шина событий, кэш | В процессе | Valkey | Valkey |
| Секреты | OpenBao (одиночный) или хранилище заказчика | Кластер OpenBao или хранилище заказчика | Кластер OpenBao или хранилище заказчика |
| Балансировка | Не требуется | L4-балансировщик | L4-балансировщик (MetalLB или внешний) |
| SLA | Не нормируется | 99,95 % | 99,95 % (цель — 99,99 %) |

Переход между профилями в базовой поставке выполняется в плановое окно: копирование BLOB и индексов средствами хранилищ, подключение кластера PostgreSQL штатной репликацией, включение Valkey изменением конфигурации. Переход без остановки сервиса — модуль «Миграция бэкенда» (п. 1.3, 3.7).

Для профиля SMB поставляется эталонная установка «всё на одной ВМ», выполняемая одной командой: бинарный файл, PostgreSQL, OpenBao и Rspamd (clamav-milter — опционально) (п. 5.6). PostgreSQL, OpenBao и Rspamd остаются внешними компонентами и не входят в бинарный файл.

## 1.3. Базовая поставка и дополнительные модули

Базовая поставка — минимальный состав, достаточный для замены Microsoft Exchange в типовой организации (п. 1.1). Остальные функции выделены в дополнительные модули:

- весь код, включая модули, открыт под лицензией продукта (п. 7.1) и находится в одном репозитории;
- модуль — набор крейтов, подключаемых как cargo feature; официальная сборка включает все модули, модуль активируется в config.yaml (`modules.<имя>.enabled`); механизм лицензионных ключей не предусматривается;
- модуль использует только точки расширения ядра (п. 2.5) и не изменяет код ядра;
- заделы под модули (структуры данных, интерфейсы, события) входят в базовую поставку с первого выпуска.

**Таблица: Дополнительные модули**

| Модуль | Содержание | Заделы в базовой поставке |
|---|---|---|
| Мультитенантность | Несколько организаций на одной инсталляции: свои каталоги и поставщики удостоверений, делегированное администрирование, политики и ограничения организации, отчёты потребления, раздельные ключи шифрования | Организация (tenant) в модели данных и API (п. 3.8) |
| Соответствие требованиям | Политики хранения, Legal Hold, журналирование переписки, eDiscovery (поиск по множеству ящиков с выгрузкой) | События ядра и точки принятия решений (п. 2.5), журнал аудита (п. 5.2) |
| Шардирование | Несколько кластеров PostgreSQL, размещение ящиков и перенос между шардами | Признак шарда в ключах, справочник шардов (п. 3.6) |
| Миграция бэкенда | Переход SMB → Enterprise и смена BLOB-хранилища без остановки | Интерфейс BlobStore, ключи объектов без привязки к бэкенду (п. 3.7) |
| Межсайтовый DR | Подтверждение доставки после репликации на резервную площадку, процедуры переключения площадок | Инвариант W (п. 3.5) |
| Развёртывание | Графический редактор топологии (хосты, роли, хранилища, сеть) и автоматическая установка по ней через эталонные Ansible-роли и Helm-чарт | JSON Schema конфигурации, thepost doctor --json, эталонные Ansible и Helm (п. 5.5, 5.6) |
| Веб-клиент | SPA поверх JMAP: почта, календари, контакты, задачи; веб-консоль администратора; вход по SAML 2.0 | JMAP, Admin API |
| Миграция с внешних систем | Импорт из Microsoft Exchange (EWS), PST, IMAP-источников | Admin API импорта (п. 5.4) |
| Генератор нагрузки | Генератор корпуса и сценариев с реалистичным распределением размеров, вложений и дублей | — |
| ГОСТ-TLS | Криптографические алгоритмы ГОСТ в TLS | Реализация TLS в одном модуле ядра (п. 6.2) |
| Правила потока почты | Правила организации (по модели transport rules Exchange): дисклеймер, блокировка и перенаправление по атрибутам, модерация, копия, изменение заголовков | Точки принятия решений при доставке и отправке (п. 2.5) |

**Обоснование.** Минимальная база ускоряет выход MVP и снижает объём кода, который должен быть готов к первому выпуску. Заделы в модели данных и интерфейсах с первого выпуска исключают переработку схемы и ядра при добавлении модулей; запрет на изменение ядра модулями сохраняет его тестируемость и стабильность.
