# Приложение Б. Рассмотренные и отклонённые альтернативы

**Таблица: Отклонённые альтернативы**

| Задача | Выбрано | Отклонено | Причина |
|---|---|---|---|
| Модель развёртывания | Модульный монолит с ролями | Микросервисы отдельными бинарными файлами | Противоречит единому бинарному файлу; сетевые вызовы между сервисами без выигрыша — роли дают ту же изоляцию и масштабирование |
| Входной шлюз | L4-балансировщик заказчика | Envoy, Nginx, Traefik | STARTTLS и проверка подлинности почты выполняются ядром; прокси добавляет компонент без функций |
| СУБД метаданных | PostgreSQL 16+ | ClickHouse | Аналитическая колоночная СУБД без транзакций; метаданные почты — частые точечные изменения |
|  |  | Собственное хранилище (RocksDB + Raft) | Годы разработки, наибольший риск корректности системы |
|  |  | FoundationDB | Редкие компетенции, сложная эксплуатация |
|  |  | YugabyteDB, TiDB | Тяжелее PostgreSQL; масштаб закрывается шардированием по ящикам |
|  |  | SQLite на ящик в S3 | Общие ящики, ACL, free/busy, очередь и дедупликация требуют общей БД; асинхронная репликация WAL (RPO > 0) |
| HA СУБД | Средства заказчика по требованиям п. 3.1; эталоны стенда — pg_auto_failover, CloudNativePG | Встроенная оркестрация | Самостоятельная задача смежных систем |
|  |  | Patroni как эталон | Требует Python; у части заказчиков исполнение интерпретаторов запрещено |
| Объектное хранилище (эталон) | SeaweedFS | Ceph RGW | Тяжёлая эксплуатация; продукту нужен только S3 API |
|  |  | MinIO | AGPL-3.0, изменения модели распространения |
| Поиск | Tantivy во всех профилях | OpenSearch | JVM-кластер ради поиска в пределах одного ящика |
|  |  | Quickwit | Ориентирован на неизменяемые журналы, а не на изменяемые ящики |
|  |  | PostgreSQL tsvector | Второй механизм поиска без выигрыша |
| Извлечение текста вложений | Встроенный экстрактор в sandbox | Apache Tika (ICAP / HTTP) | Внешний JVM-сервис, нарушает профиль SMB |
| Сигналы между узлами | PostgreSQL LISTEN/NOTIFY (кластер), канал в памяти (один процесс) | Valkey (pub/sub) | Дополнительный продукт и независимая точка отказа; выигрыш в скорости при расчётной нагрузке не нужен |
|  |  | Eclipse Zenoh, собственная сеть узлов | Собственный распределённый протокол в процессе: больше кода и режимов отказа |
| Кэш в процессе | moka | dashmap | Нет TTL и ограничения размера |
| Антиспам, антивирус | Внешние системы, интерфейс Milter | ICAP, встроенный фильтр | Вне назначения продукта; Milter поддерживают Rspamd и ClamAV |
| Мониторинг | Экспорт /metrics и OTLP | Zabbix, собственные дашборды | Вне назначения продукта |
| Резервное копирование | Внешние СРК + сервисные функции продукта | pg_dump, Barman | pg_dump не обеспечивает PITR; Barman — GPL; выбор СРК — за заказчиком |
| Разбор MIME | mail-parser | mailparse, парсер на nom | Наиболее полная реализация RFC 5322, 2045–2049 на Rust |
| Sieve | Собственная реализация | sieve-rs | Лицензия AGPL-3.0-only |
| SAML 2.0 | Вместе с веб-клиентом | В ядре | Без веб-интерфейса не используется |
| Основа кодовой базы | Собственная архитектура + пермиссивные библиотеки Stalwart; Stalwart — эталон тестов совместимости | Форк Stalwart целиком | AGPL для всего проекта; функции уровня Enterprise (мультитенантность, архив и восстановление удалённого, read-реплики, шардирование BLOB) не входят в открытую редакцию; KV-ориентированная модель хранения не совпадает с целевой; высокая стоимость синхронизации с upstream |
