# APP-29: календари и контакты в узле (роль dav) — ручная проверка

Нужны: стенд с ролями `jmap` и `dav` за TLS (сборка и запуск — `docs/DEV.md`; эталон `--profile smb` —
`docs/manual-tests/CMP-01.md`), публичное имя (например, `mail.example.org`) с сертификатом, которому доверяют
устройства, учётная запись `ivan@example.org` с паролем приложения (`docs/manual-tests/APP-19.md`). Клиенты:
Thunderbird 128+, iOS 17+, macOS 14+, DAVx5 4.4+ (Android 13+). Во всех клиентах — один адрес сервера
`mail.example.org`, имя входа — адрес почты, пароль — пароль приложения.

Проверяется подключение узла: слушатель, вход, автонастройка. Сценарии работы с событиями и карточками —
`docs/manual-tests/DAV-08.md` (календари) и `docs/manual-tests/DAV-11.md` (контакты).

Результат каждого шага записывается в таблицу в конце: «ок» или замечание (что сделано, что ожидалось, что
получено, версия клиента).

## Узел
Обозначения: `U=ivan@example.org:<пароль приложения>`, `S=https://mail.example.org`.

1. **Общий порт с JMAP** (в конфигурации `http.jmap`, ключа `http.dav` нет):
   `curl -si $S/.well-known/caldav` и `curl -si $S/.well-known/carddav` — `301`, `Location` оканчивается на `/dav/`;
   `curl -si $S/.well-known/jmap` — ответ JMAP (`401` без входа), как раньше.
2. **Вход паролем приложения:** `curl -su $U -X PROPFIND -H 'Depth: 1' $S/dav/calendars/ivan@example.org/` — `207`,
   в ответе `calendar/` и `tasks/`; то же для `$S/dav/addressbooks/ivan@example.org/` — `207`, адресная книга
   по умолчанию.
3. **Отказ во входе:** тот же запрос с неверным паролем — `401` с `WWW-Authenticate: Basic`; без заголовка
   `Authorization` — `401`.
4. **Защита от перебора:** неверный пароль подряд больше порога `auth.abuse` — отказ и для верного пароля
   до истечения блокировки (общая с IMAP и JMAP: после блокировки вход в IMAP с тем же именем тоже отклоняется).
5. **Глобальная адресная книга** (только при настроенном каталоге `auth.ldap`):
   `curl -su $U -X PROPFIND -H 'Depth: 1' $S/dav/addressbooks/ivan@example.org/` — в ответе есть `gal/` с именем
   «Организация»; `PUT` в `gal/` — `403`. Без `auth.ldap` коллекции `gal/` нет.
6. **`thepost doctor`:** строки `dav.listener` и `dav.well_known.caldav`, `dav.well_known.carddav` — `OK`.
   С `jmap.autoconfig.caldav: /caldav/` — `FAIL` у `dav.well_known.caldav` с подсказкой.
7. **Отдельный порт:** добавить `http: { dav: { listen: 0.0.0.0:8443 } }`, перезапустить.
   `curl -su $U -X PROPFIND -H 'Depth: 0' https://mail.example.org:8443/dav/` — `207`;
   `curl -si https://mail.example.org:8443/.well-known/caldav` — `301` на `/dav/`;
   `curl -si $S/dav/` (порт 443) — `404`; `thepost doctor` — `WARN` у `dav.well_known.*`, пока
   `jmap.autoconfig.caldav` и `carddav` не заданы полным адресом `https://mail.example.org:8443/dav/`.
   После проверки ключ `http.dav` убрать.
8. **Узел без роли dav** (`roles` без `dav`): `curl -si $S/dav/` — `404`, остальные протоколы работают.

## Клиенты (один адрес сервера)
1. **Thunderbird.** «Календарь» → «Новый календарь» → «В сети» → имя пользователя и адрес `mail.example.org` →
   найдены «Календарь» и «Задачи». «Адресная книга» → «Новая адресная книга» → «Добавить адресную книгу CardDAV» →
   тот же адрес → найдена адресная книга (и «Организация» при `auth.ldap`).
2. **iOS.** «Настройки» → «Календарь» → «Учётные записи» → «Другое» → «Учётная запись CalDAV»: сервер
   `mail.example.org`. То же — «Контакты» → «Учётная запись CardDAV». Ожидается: проверка учётной записи проходит,
   календари и контакты появляются в приложениях.
3. **iOS и macOS, профиль.** Открыть `https://mail.example.org/mail/profile.mobileconfig` (порядок — как в
   `docs/manual-tests/JMAP-22.md`), установить профиль. Ожидается: одной установкой добавлены почта,
   календари и контакты; профиль показан как проверенный.
4. **macOS вручную.** «Системные настройки» → «Учётные записи интернета» → «Другая» → «Учётная запись CalDAV» и
   «Учётная запись CardDAV», тип «Вручную», сервер `mail.example.org`.
5. **DAVx5.** «Добавить учётную запись» → «Вход по URL и имени пользователя» → `mail.example.org` → найдены
   календарь, задачи и адресная книга.
6. **Сквозная проверка.** Событие, созданное в одном клиенте, видно в остальных; контакт — так же.
