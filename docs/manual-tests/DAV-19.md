# DAV-19: бронирование переговорных и делегирование — ручная проверка клиентами

Нужны: стенд с ролью `dav` за TLS (сборка и запуск — `docs/DEV.md`), в узле подключены права общего доступа
(`tp_dav::Deps::sharing`, x/jmap-19), хранилища общего доступа (`tp_dav::router_shared` с `SharingStores`) и
бронирование (`ItipInbox::with_booking`); публичное имя (например, `mail.example.org`) с доверенным сертификатом. Учётные записи с паролями
приложений: `ivan@example.org`, `petr@example.org`, `olga@example.org`. Клиенты: Календарь macOS 14+ и
Thunderbird 128+ (для делегирования — Календарь macOS; iOS — по возможности). Адрес сервера —
`https://mail.example.org/dav/`, имя входа — адрес почты.

Результат каждого шага записывается в таблицу в конце: «ок» или замечание (что сделано, что ожидалось, что
получено, версия клиента; по возможности — запрос и ответ из журнала клиента).

## Подготовка
1. Переговорная через Admin API (`<токен>` — токен администратора организации, `<org>` — организация):
   `curl -s -H 'Authorization: Bearer <токен>' -H 'Content-Type: application/json' -X POST
   https://mail.example.org/api/v1/orgs/<org>/resources -d '{"login":"baikal@example.org","display_name":"Переговорная «Байкал»"}'`
   — правила по умолчанию: автоматическое принятие без пересечений, до суток, на 180 дней вперёд.
2. Рабочее время переговорной: `PUT …/resources/<id baikal>/booking-policy` с
   `{"auto_accept":true,"working_hours":{"timezone":"Europe/Moscow","days":["monday","tuesday","wednesday","thursday","friday"],"from":"09:00","to":"18:00"}}`.
3. Вторая переговорная «Енисей» с правилом «только Иван»: `PUT …/booking-policy` с
   `{"bookers":{"type":"only","accounts":["<id ivan>"],"groups":[]}}`.
4. Подключить учётные записи `ivan` и `petr` в Календаре macOS («Системные настройки» → «Учётные записи
   интернета» → «Другая» → «Учётная запись CalDAV», вручную) и в Thunderbird («Календарь» → «Новый календарь» →
   «В сети»).
5. Проверка без клиента: `curl -su ivan@example.org:<пароль> -X REPORT -H 'Depth: 0'
   https://mail.example.org/dav/principals/ --data '<cs:calendarserver-principal-search
   xmlns:cs="http://calendarserver.org/ns/" xmlns:d="DAV:" context="location"><cs:search-token>байк</cs:search-token></cs:calendarserver-principal-search>'`
   — в ответе `/dav/principals/baikal@example.org/`, `calendar-user-type` — `ROOM`.

## Сценарии
1. **Выбор переговорной.** macOS: новая встреча → поле «Место» или «Добавить приглашённых» → начать вводить
   «Байк». Ожидается: «Переговорная «Байкал»» в подсказках как место (значок переговорной). Thunderbird:
   «Пригласить участников» → найти `baikal@example.org` → тип участника «Помещение».
2. **Свободно — принято.** Иван: встреча завтра (будний день) 11:00–12:00 по Москве с переговорной «Байкал» и
   Петром. Ожидается: у переговорной статус «Принято» (macOS — зелёная отметка у участника, Thunderbird —
   «Принял»); в календаре переговорной (`curl -X PROPFIND -H 'Depth: 1'` на
   `/dav/calendars/baikal@example.org/calendar/` от администратора-представителя, см. сценарий 6) — событие.
3. **Конфликт — отказ.** Петр: встреча завтра 11:30–12:30 с «Байкалом». Ожидается: статус переговорной
   «Отклонено»; в ответе — комментарий «Отклонено: ресурс занят» (Thunderbird показывает его в приглашении,
   macOS — в подробностях участника, если отображает `COMMENT`); у Ивана бронь не изменилась.
4. **Перенос.** Иван переносит встречу из п. 2 на 14:00–15:00. Ожидается: переговорная снова «Принято», в её
   календаре одно событие на новое время (старая бронь снята).
5. **Вне рабочего времени и недопустимый организатор.** Иван: встреча завтра 19:00–20:00 с «Байкалом» —
   «Отклонено», причина «вне рабочего времени ресурса». Петр: любая встреча с «Енисеем» — «Отклонено», причина
   «организатору не разрешено бронировать ресурс»; Иван — «Принято».
6. **Делегирование (DAV-18).** macOS, учётная запись Ивана: «Календарь» → «Настройки» → «Учётные записи» →
   учётная запись → «Делегирование» → «Изменить» → добавить Петра с «Чтение и запись». Ожидается: у Петра в
   macOS в «Делегирование» появляется Иван; включить флажок «Показать» — календари Ивана видны у Петра.
   Петр создаёт в календаре Ивана встречу с Ольгой. Ожидается: Ольга получает приглашение от Ивана
   (`ORGANIZER` — Иван, `SENT-BY` — Петр: Thunderbird показывает «от имени»); Петр с правом «Только чтение»
   создать событие не может (macOS сообщает об ошибке прав).
7. **Ответственный за переговорную.** Правило «Байкала» `auto_accept: false`; администратор назначает Ольгу
   представителем ресурса (`PUT …/accounts/<id baikal>/delegates/<id olga>` с `{"level":"write"}`). Иван
   бронирует «Байкал» — статус «Под вопросом»; Ольга в macOS через «Делегирование» открывает календарь
   переговорной и видит событие.
8. **Общий календарь (DAV-17).** macOS, Иван: правый клик по календарю «Календарь» → «Поделиться календарем» →
   добавить Петра (просмотр). Ожидается: у Петра календарь «Календарь (Иван)» появляется в списке, событие не
   редактируется (macOS показывает замок); после смены права на «Просмотр и правка» Петр меняет событие;
   «Прекратить общий доступ» — календарь исчезает у Петра.
