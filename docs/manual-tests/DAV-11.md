# DAV-11: контакты CardDAV — ручная проверка клиентами

Нужны: стенд с ролью `dav` за TLS (после APP-29; сборка и запуск — `docs/DEV.md`), публичное имя
(например, `mail.example.org`) с сертификатом, которому доверяют устройства, учётная запись
`ivan@example.org` с паролем приложения. Клиенты: Thunderbird 128+, Контакты iOS 17+ и macOS 14+, DAVx5 4.4+
(Android 13+, приложение «Контакты»), GNOME Evolution 3.50+. Адрес сервера во всех клиентах —
`https://mail.example.org/dav/` (или автонастройка через `/.well-known/carddav`), имя входа — адрес почты.

Результат каждого шага записывается в таблицу в конце: «ок» или замечание (что сделано, что ожидалось, что
получено, версия клиента; по возможности — запрос и ответ из журнала клиента).

## Подготовка
1. Учётная запись без адресных книг: первый вход любого клиента создаёт книгу «Контакты». Проверка без клиента:
   `curl -su ivan@example.org:<пароль> -X PROPFIND -H 'Depth: 1' https://mail.example.org/dav/addressbooks/ivan@example.org/`
   — в ответе `contacts/` (и `gal/` «Организация», если подключён каталог); повторный запрос не добавляет книг.
2. Подключить учётную запись:
   - Thunderbird: «Адресная книга» → «Создать адресную книгу» → «Добавить адресную книгу CardDAV» → имя входа и
     адрес `https://mail.example.org/dav/` → найдена «Контакты».
   - iOS: «Настройки» → «Контакты» → «Учётные записи» → «Другое» → «Учётная запись CardDAV».
   - macOS: «Системные настройки» → «Учётные записи интернета» → «Другая» → «Учётная запись CardDAV» (вручную).
   - DAVx5: «Добавить учётную запись» → «Вход по URL и имени пользователя» → отметить «Контакты»; в настройках
     учётной записи — «Группы контактов: отдельные vCard».
   - Evolution: «Файл» → «Создать» → «Адресная книга» → тип CardDAV → «Найти адресные книги».

## Сценарии (каждый — в каждом клиенте)
1. **Создание.** Контакт «Проверка <клиент>»: имя, фамилия и отчество кириллицей, организация и должность, два
   адреса почты (рабочий — основной, личный), два телефона (мобильный, рабочий), почтовый адрес, день рождения,
   заметка в две строки. Ожидается: контакт появляется в остальных клиентах после синхронизации; все поля на
   месте, типы адресов и телефонов и отметка «основной» совпадают, кириллица не искажена.
2. **Правка в другом клиенте.** Контакт, созданный в iOS (vCard 3.0), изменить в Thunderbird или DAVx5 (vCard 4.0),
   и наоборот: добавить телефон, сменить должность. Ожидается: правка видна в исходном клиенте, остальные поля не
   потеряны (в том числе свои метки iOS «Домашняя страница» и т. п.), дубликат не появляется.
3. **Фото.** Добавить контакту фото (до 500 КБ). Ожидается: фото видно в остальных клиентах. Фото больше
   `dav.max_photo_size` (по умолчанию 512 КиБ после декодирования; проверить снимком камеры без сжатия или
   `curl -X PUT`): сервер отвечает 403 `max-resource-size`, клиент сообщает об ошибке или уменьшает фото, остальные
   контакты синхронизируются.
4. **Группы.** Создать группу «Команда <клиент>» из двух контактов (iOS не создаёт группы — проверять показ; macOS,
   DAVx5, Evolution, Thunderbird — «список рассылки»). Ожидается: группа и её состав видны в клиентах, которые
   показывают группы; группа, созданная в macOS (`X-ADDRESSBOOKSERVER-KIND`), видна в DAVx5 и Evolution, созданная в
   DAVx5 (`KIND:group`) — в macOS и iOS.
5. **Версия по запросу.** `curl -H 'Accept: text/vcard; version=4.0' …/contacts/<карточка iOS>.vcf` — `VERSION:4.0`,
   `PREF=1` вместо `TYPE=pref`; с `version=3.0` для карточки DAVx5 — `VERSION:3.0`, фото — `PHOTO;ENCODING=b`;
   без `Accept` — как записал клиент.
6. **Поиск.** Thunderbird: поиск по адресной книге на сервере не выполняется (локальный) — пропустить. macOS и
   Evolution (поиск в книге), `curl -X REPORT` с `addressbook-query` по части фамилии кириллицей в другом
   регистре и по части адреса почты. Ожидается: найдены нужные контакты.
7. **Удаление.** Удалить контакт из п. 1 и группу из п. 4. Ожидается: исчезают во всех клиентах.
8. **Синхронизация двух устройств.** На двух устройствах одной учётной записи: на первом создать контакт, на
   втором — изменить другой и удалить третий, синхронизировать оба. Ожидается: состав книги одинаков. Затем без
   синхронизации между правками изменить один и тот же контакт на обоих (на первом — телефон, на втором —
   должность); синхронизировать первое, затем второе. Ожидается: второй клиент сообщает о конфликте или забирает
   версию сервера; на сервере — одна карточка, без дубликата; итог одинаков на обоих устройствах.
9. **Офлайн-правка.** Отключить сеть, создать контакт, изменить другой, удалить третий; включить сеть и
   синхронизировать. Ожидается: все три изменения на сервере и в других клиентах.
10. **Новая адресная книга.** Создать книгу «Партнёры» из клиента (macOS, DAVx5, Evolution; Thunderbird и iOS книги
    на сервере не создают), переименовать в другом клиенте, удалить. Ожидается: имя совпадает во всех клиентах,
    после удаления книга исчезает.
11. **Отклонение недопустимых данных.** `curl -X PUT` в `contacts/`: карточка без `UID` → 403
    `valid-address-data`; `VERSION:2.1` → 403 `supported-address-data`; карточка с `UID` уже существующей → 403
    `no-uid-conflict` со ссылкой на неё. Клиентские книги не затронуты.
