# UI-09: веб-консоль — ручная проверка разделов по ролям

Нужны: стенд с ролью `admin` и собранной консолью (`docs/DEV.md`; консоль — `https://<узел>/console/`), вход через
OIDC, организация с доменом `example.org`, учётные записи `ivan@example.org` и `petr@example.org`, одна группа
рассылки с модерацией. В секции `admin.roles` config.yaml — четыре администратора: `root@example.org`
(`installation_admin`), `admin@example.org` (`organization_admin`), `oper@example.org` (`operator`),
`audit@example.org` (`auditor`). Браузер — актуальный Firefox или Chromium; открыть инструменты разработчика,
вкладку «Сеть».

Результат каждого шага — в таблицу в конце: «ок» или замечание (что сделано, что ожидалось, что получено, запрос и
ответ из вкладки «Сеть»).

## Общее (каждой ролью)
1. Вход: после входа открыт первый раздел роли, в шапке — имя входа. Запросов за пределы узла (CDN, шрифты,
   телеметрия) во вкладке «Сеть» нет.
2. Меню содержит только разделы роли (таблица ниже); ответов 403 при обходе разделов меню нет.
3. Выход и повторный вход; истёкшая сессия возвращает на экран входа.

| Раздел | администратор организации | оператор | аудитор |
|---|---|---|---|
| Организация, Домены, Учётные записи, Группы рассылки, Модерация | чтение и изменение | только чтение | нет |
| Правила организации, Транспорт, Журнал доставки | чтение и изменение | только чтение | нет |
| Журнал аудита | чтение | нет | чтение |
| Транспорт → «Инсталляция» | нет (только администратор инсталляции) | нет | нет |

## Администратор организации (`admin@example.org`)
1. **Организация и домены.** Изменить политику организации (срок корзины), добавить и удалить домен; политика домена.
2. **Учётные записи.** Поиск по началу имени входа, создание локальной записи, политика ящика; пароль приложения:
   выпуск (значение показано один раз), отзыв. Корзина: восстановить письмо из корзины и из скрытых.
3. **Правила и автоответ** (ссылка на карточке учётной записи).
   - Новый скрипт `main`: `require "fileinto"; if header :contains "subject" "отчёт" { fileinto "Отчёты"; }` →
     сохранить → «Активировать». Отправить `ivan@example.org` письмо с темой «отчёт»: письмо в папке «Отчёты».
   - Испортить текст (`fileinto;` без аргумента) → сохранить. Ожидается: скрипт не сохранён, под редактором —
     ошибки со строкой и столбцом, нажатие на позицию выделяет строку; прежний текст на узле не изменился
     (открыть скрипт заново).
   - Активный скрипт удалить нельзя (кнопки нет); «Отключить правила» → письмо с темой «отчёт» приходит во «Входящие».
   - Автоответ: включить, период — до завтра, тема и текст кириллицей → письмо от `petr@example.org` получает
     автоответ; выключить → автоответа нет. Клиент пользователя (JMAP `VacationResponse`) показывает те же значения.
4. **Правила организации.** Скрипта нет — пустой редактор. Сохранить `if address :is "from" "spam@example.net"
   { discard; }` → письмо от этого адреса не доставляется никому в организации; ошибка в тексте — как в п. 3;
   «Удалить скрипт» → доставляется.
5. **Группы и модерация.** Создать группу, изменить состав, одобрить и отклонить письмо в очереди, удалить группу.
6. **Транспорт.**
   - Принятые домены: добавить `relay.example.org` вида «внутренняя ретрансляция» с узлом назначения, изменить
     вид на «полномочный», удалить (запрос подтверждения).
   - Доверенные источники: шлюз по подсети с XCLIENT; приложение по сертификату с разрешённым отправителем
     `@example.org`; изменить, удалить.
   - Маршруты: `partner.example` с обязательным TLS и промежуточным узлом; `*` (все внешние); удалить.
   - Конфликт версий: открыть «Транспорт» в двух вкладках, в первой добавить домен, во второй (без обновления)
     удалить другой. Ожидается: отказ с кодом 409 в уведомлении, список перечитан, повтор проходит.
   - Вкладки «Инсталляция» нет.
7. **Журнал доставки.** Отправить письмо наружу и письмо несуществующему адресу. Поиск по отправителю, по
   получателю, по Message-ID (с угловыми скобками и без), по интервалу; карточка письма (нажатие на Message-ID)
   показывает события по порядку с решением, причиной и узлом.
8. **Журнал аудита.** Действия пп. 1–6 есть в журнале: имя входа, роль, метод, маршрут, код. Интервал «последний
   час»; отбор по администратору и по действию (`DELETE`); переход «Дальше» и «Назад».

## Оператор (`oper@example.org`)
1. Все разделы, кроме журнала аудита, открываются и показывают данные.
2. Кнопок изменения нет: «Создать», «Удалить», «Изменить», «Добавить …», «Сохранить скрипт», «Активировать»,
   «Сохранить автоответ». Замечание — любая кнопка, после нажатия которой узел отвечает 403.
3. Адрес `/console/audit` вручную: узел отвечает 403, консоль показывает ошибку, данных нет.

## Аудитор (`audit@example.org`)
1. После входа открыт «Журнал аудита»; в меню — только он.
2. Журнал: интервал, отбор, страницы — как у администратора организации.
3. Адреса `/console/accounts`, `/console/transport` вручную: узел отвечает 403, данных нет.

## Администратор инсталляции (`root@example.org`)
1. В шапке — поле выбора организации; смена организации перечитывает разделы.
2. «Транспорт» → «Инсталляция»: принятые домены всех организаций; источники кластера и организаций. Добавить
   общий шлюз кластера, изменить, удалить; у источника организации кнопок нет.
