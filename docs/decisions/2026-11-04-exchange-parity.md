# 2026-11-04. Соответствие функциям Exchange: закрытие пробелов

Решение владельца (обсуждение 2026-11-04). Перечень функций Exchange Server 2019 (104) со статусами — приложение И SRS;
перечень сверяется при каждом изменении функционального состава.

Принцип: редкие, заброшенные и специфические протоколы не используются — только распространённые стандарты.

## Подключение клиентов и удобство пользователя (база)
- Автонастройка клиентов: записи DNS SRV (RFC 6186, RFC 6764), автонастройка Thunderbird (`autoconfig.<домен>`),
  `/.well-known/jmap`, `/.well-known/caldav`, `/.well-known/carddav`, профиль `.mobileconfig`; Autodiscover Microsoft — нет.
- Отложенная отправка и отмена отправки: JMAP `EmailSubmission.sendAt`, `maxDelayedSend`, `undoStatus`; очередь хранит срок выпуска.
- Личные списки надёжных и заблокированных отправителей ящика, применяются при доставке поверх вердикта антиспама.
- Статус доставки для пользователя: JMAP `EmailSubmission.deliveryStatus` из журнала доставки.

## Получатели и адресная книга (база)
- Почтовые контакты: из каталога (класс и ветка — настройка) и локальные через Admin API; в GAL и в раскрытии групп.
- Динамические группы рассылки: фильтр по атрибутам каталога, состав вычисляется при раскрытии.
- Иерархическая адресная книга: руководитель, подразделение, старшинство из каталога; путь подразделения — `ORG` в vCard,
  дерево — JMAP-расширение и Admin API.
- Самообслуживание и политики именования групп — не делаются (источник групп — каталог).

## Хранение и соответствие требованиям
- Архив ящика (база): ветка папок `\Archive` (RFC 6154), своя квота, автоперенос по возрасту по политике; холодный уровень
  хранения архива — модуль «Соответствие требованиям».
- Удалённые ящики (база): при исчезновении учётной записи из каталога ящик отключается и хранится 30 дней (политика),
  восстанавливается, подключается к другой учётной записи или выгружается; окончательное удаление — через точку принятия решений;
  синхронизация, удаляющая больше порога учётных записей (5 %), останавливается с оповещением.
- Аудит доступа к ящику (база): доступ не владельца — по умолчанию; действия владельца (удаление, перемещение, отправка,
  правила и пересылка) — по политике; чтение владельцем не журналируется; журнал аудита и выгрузка в SIEM.
- DLP — внешние системы: профиль Milter для исходящей почты (база), промежуточный узел, копия через журналирование (модуль).

## Календари
- Публикация календаря по ссылке ICS (токен, отзыв, уровень детализации) и политика организации для внешнего доступа (база).
- Занятость между организациями: ссылки VFREEBUSY (FBURL в vCard, calFBURL в каталоге) с политикой доступа (база);
  модуль «Федерация календарей» — собственный протокол (обсуждение — issue #187) и коннекторы к Exchange Server (EWS)
  и Microsoft 365 (Graph). iSchedule и FUTURERELEASE не используются.
