# 2026-10-31 — очередь мержит merge-коммитом

Основание — лишняя ручная работа с цепочками PR (PR зависимости `x/<полоса>-dep` или контракта, на нём волна):
при методе REBASE очередь переписывала нижний коммит, верхний PR видел чужие файлы (`changes`: «2 полосы»),
требовал update-branch, а при пересечении правок — перенос коммита в новый PR (#69 → #83, #105 → #107).

- Метод очереди `main` — MERGE (ruleset `mail`); коммиты PR попадают в main без переписывания.
- Цепочка PR: верхняя ветка строится на нижней; после мержа нижнего верхний PR сам показывает только свои файлы,
  ветку не обновлять и не пересоздавать.
- История main нелинейная — принято владельцем.
