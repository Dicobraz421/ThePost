# 2026-11-11: сначала работающее изделие

Решение владельца: план приоритизируется по принципу «базовые функции — первыми». Цель — как можно раньше получить
работающий продукт; всё, без чего почта работает (соответствие Exchange, внешние встречи, шарды, Enterprise, тонкие
настройки), — дальше по плану. «Нужно срочно работающее изделие, остальные нюансы дотащим потом».

## Как применяется
- `docs/PLAN.md`, раздел «Порядок работ»: этап 1 «почта работает на стенде SMB», этап 2 «пилот SMB», этап 3 «после пилота».
- Оркестратор запускает готовые волны самого раннего незавершённого этапа; следующего — только на свободные полосы;
  этап 3 — после приёмки этапа 2.
- Зависимость «по очерёдности полосы» не держит базовую волну за волной позднего этапа: в полосе первой идёт волна раннего этапа
  (так `app-18` идёт раньше `app-17`, `meta-26` — раньше `meta-25`).
- Новая карточка получает этап при постановке в план; по умолчанию — этап 3, если без неё почта на стенде работает.
- Приёмка этапа 1 — ручная проверка `docs/manual-tests/CMP-01.md` целиком на бете, клиенты Thunderbird и Postman.
