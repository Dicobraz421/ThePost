## Сделать
- Приёмка консоли 0.2.0 (дефекты 1, 2, 4): `GET /api/v1/orgs/<несуществующий UUID>` — 200 с пустой политикой,
  `PUT …/policy` на чужом UUID записывает политику «организации-призрака». Слой доступа (`guard`) после проверки области роли отвечает 404 на
  любом маршруте `/api/v1/orgs/{org}/…`, если организации нет среди организаций инсталляции (без модуля
  «Мультитенантность» — только организация по умолчанию). Администратору другой организации по-прежнему 403:
  существование чужих не раскрывается. `GET /api/v1/orgs` — из того же списка.
- Ошибки разбора — 422 текстом `axum` (тело) и 400 текстом (строка запроса). Один отказ для всех маршрутов:
  `crate::extract::{Json, Query, Path}` поверх извлекателей `axum` — 400 `application/problem+json`, в `detail` — поле и
  причина; слишком большое тело — 413 problem+json. Проверка смысла в обработчиках (422 Sieve, 422 пустого `PATCH`) —
  без изменений.
- Схема: общие отказы объявлены у всех операций (`CommonErrors` в `openapi_spec()`): маршрут организации — 404 и 400,
  операция с телом или параметрами запроса — 400. Копия консоли (CI-11) и `schema.d.ts` — в том же PR.
- «Очередь» в консоли не делается: в Admin API нет операций очереди доставки. Нужны (отдельные карточки): контракт
  `QueueStore` — список записей организации (получатели, статус, попытки, срок следующей, последняя ошибка) и повтор
  сейчас (срок попытки — `now`); Admin API — `GET /api/v1/orgs/{org}/queue`, `POST …/queue/{id}/retry`; затем экран UI.

## Приёмка
- Тест: несуществующая организация — 404 на `GET`, списке, аудите и `PUT /policy`; призрак в `GET /api/v1/orgs` не
  появляется; отказ записан в аудит с 404; администратору организации — 403.
- Тест: неверный тип поля, неизвестное поле, неверный `since`/`limit`, неверный UUID пути — 400 problem+json, в
  `detail` — имя поля.
- Тест: каждая операция объявляет 400/404 по правилу выше; CI-11 — копия консоли совпадает со схемой.
