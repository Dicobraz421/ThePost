## Сделать
- `tp_tui::node::save` пишет `config.yaml` на месте: сбой посередине (место на диске, обрыв питания) оставляет
  обрезанный файл, а узел при перечитывании может прочитать его наполовину записанным.
- Атомарная замена: новый текст — во временный файл в том же каталоге (`<имя>.<pid>.tmp`, создаётся с правами
  `0600`), владелец и права — как у прежнего файла, `fsync`; временный файл проходит `thepost config check`
  (отдельный файл `.check` больше не нужен); резервная копия `config.yaml.bak` — как сейчас; `rename` поверх;
  `fsync` каталога. При любой ошибке временный файл удаляется, прежний файл не тронут.
- Символическая ссылка остаётся ссылкой: заменяется файл, на который она указывает.
- Сохранить владельца не удалось (правит не владелец и не root) — ошибка записи, файл не тронут: иначе файл сменил
  бы владельца и узел мог бы его не прочитать.

## Как делают другие
- `visudo` (https://www.sudo.ws/docs/man/visudo.man/): правка во временной копии, проверка синтаксиса, затем замена
  `sudoers` переименованием; права и владелец выставляются заново. У нас права и владелец берутся у прежнего файла
  (у `config.yaml` они задаются установкой), одновременную правку ловит проверка «файл изменён после чтения» вместо
  файла блокировки.
- `crontab -e` (https://man7.org/linux/man-pages/man1/crontab.1.html): правка во временном файле, установка — новой
  таблицей целиком, частично записанной таблицы демон не видит.
- `systemctl edit` (https://www.freedesktop.org/software/systemd/man/latest/systemctl.html): правка во временном
  файле рядом с целевым, на место он встаёт только после выхода из редактора; пустой файл — отмена.

## Приёмка
- Тесты: после записи рядом только файл и `config.yaml.bak`, после отказа проверки — только файл; на Unix — новый
  inode, права `0640` и владелец прежнего файла, символическая ссылка остаётся ссылкой.
