Решение владельца 13.11. После 0030 `addressbook-query` ищет по `dav_objects.search` (DAV-24, PR #636); строки
заполняет `tp_dav::index::card` при записи. У карточек, записанных до 0030, строк нет — поиск их не находит, пока
клиент не перезапишет карточку.

## Сделать
- Миграция: признак «поисковые строки посчитаны» у `dav_objects` — у существующих строк `false`, у новых `true`
  (значение по умолчанию без перезаписи таблицы); частичный индекс по непосчитанным карточкам. Запись объекта
  (`put_object`) ставит признак.
- `PgMeta::reindex_cards(index)`: по всем шардам, пачками `meta.dav.card_reindex_batch` с паузой
  `meta.dav.card_reindex_pause`; тело читается короткой транзакцией, строки считает переданная функция вне
  транзакции, каждая карточка обновляется своим запросом при неизменном `modseq` (параллельная запись клиента
  выигрывает). `ModSeq` и ETag не меняются: тело то же. Тело без строк (не разбирается) — признак ставится, строки
  пустые. Функцию передаёт узел (`tp_dav::index::card`): у `tp-meta` нет зависимости от `tp-dav`.
- Повторный запуск: непосчитанных нет — один запрос по пустому частичному индексу на шард.

## Приёмка
- PostgreSQL: карточка, записанная до миграции, после пересчёта находится `find_cards`; повторный пересчёт
  ничего не меняет (0 карточек, `modseq` прежний); новая запись после миграции уже посчитана.
- Вызов из узла (роль maintenance, один раз в фоне после запуска) — полоса app, отдельной карточкой.
