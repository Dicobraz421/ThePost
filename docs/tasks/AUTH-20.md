PLT-34 (#707) приводит адрес клиента к канонической форме при приёме соединения (`Listener::accept`, PROXY v2,
служебный HTTP): IPv4, отображённый в IPv6 (`::ffff:a.b.c.d`), приходит адресом IPv4. Нормализация в
`AbuseGuard` (AUTH-19, `source_ip()`) стала вторым путём; правило владельца — второй путь не оставлять.

## Сделать
- Убрать `source_ip()` из `abuse.rs`: счётчики (`failure`) и проверка блокировок (`check`) берут `Attempt::ip`
  как есть.
- Убрать описание нормализации из шапки модуля; у `Attempt::ip` — адрес в канонической форме (PLT-34).
- Тесты `abuse/tests.rs` — адреса IPv4 без формы `::ffff:`; тест на равенство `::ffff:a.b.c.d` и `a.b.c.d`
  убрать (проверяется у слушателя, PLT-34).

## Приёмка
- В `tp-auth` нет `to_canonical`.
- Адреса IPv4 из разных `/24` не складываются в одну подсеть; 100 неудач из `10.0.1.0/24` блокируют только эту `/24`.
