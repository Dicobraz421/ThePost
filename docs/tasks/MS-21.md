## Сделать
- `MailStore::ingest`: в одной транзакции БД — письмо, привязка к беседе (`ThreadStore::bind`) и применённые
  политики беседы: удержание беседы — на новое письмо; `ThreadRule` — `AlwaysMove` (папка вместо выбранной правилами),
  `Ignore` (в корзину), `AlwaysKeyword` (ключевое слово). Обращений к BLOB внутри транзакции нет (тело — до неё, как
  сейчас).
- Память беседы для аномалий (типы вложений, домены ссылок, `Reply-To`) обновляется в той же транзакции.
- Беседа письма для выдачи (`MailStore`) — из привязки, а не из `thread_key`; `thread_key` остаётся только ключом
  присоединения и фоновой привязки старых писем (META-86).

## Как делают другие
- Действия по беседе для будущих писем — EWS `ApplyConversationAction`
  (https://learn.microsoft.com/en-us/exchange/client-developer/web-service-reference/applyconversationaction-operation);
  атомарная загрузка пачки — IMAP MULTIAPPEND (https://www.rfc-editor.org/rfc/rfc3502.html). Транзакции «письмо +
  беседа + политики» у других нет — наше отличие.

## Приёмка
- Тесты на in-memory `tp-testkit`: ответ попадает в беседу исходного письма; письмо в беседу с `AlwaysMove` — в
  заданной папке; в удержанную беседу — удержано; сбой привязки откатывает письмо целиком.
