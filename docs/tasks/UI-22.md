## Сделать
- Действующий брендинг — поверх темы UI-19: цвета ролей из ответа сервера (`light` или `dark` — по теме консоли)
  заменяют соответствующие токены antd (главная кнопка, выделение, рамки, ссылки); своих расчётов контраста в консоли
  нет. `null` — тема IT TASK из `design/tokens.toml`, как сейчас.
- Страница входа: `GET /api/v1/public/branding` — сначала без `domain`, затем по домену из введённого имени входа
  (после `@`, с задержкой); знак и название вместо IT TASK, `document.title` — название продукта. После входа — набор
  `effective` своей организации (администратор установки — уровня установки); знак и название в шапке.
- Раздел «Брендинг»: уровень установки (администратору установки) и вкладка организации — название, два цвета
  (`ColorPicker` antd, ввод `#RRGGBB`), загрузка знака (`Upload`, только PNG, проверка размера до отправки),
  предпросмотр шапки и выделения, сброс с подтверждением. Ошибки 422 — у поля цвета с текстом `detail` сервера.
- Нет знака или он не загрузился — только название.

## Приёмка
- Тесты: тема строится из ответа сервера, при `null` — из токенов; страница входа перезапрашивает брендинг по домену;
  форма показывает ошибку контраста у поля акцента; сброс возвращает тему установки.
- Ручная проверка на стенде: свой брендинг установки и организации — вход, шапка, светлая и тёмная темы.
