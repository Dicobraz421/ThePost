## Сделать
- Действующий брендинг — поверх темы UI-19: цвета всех ролей из ответа сервера (`light` или `dark` — по теме консоли)
  заменяют соответствующие токены antd (фоны `screen`/`panel`, текст, главная кнопка — `fkBg`/`fkFg`, выделение —
  `sel`/`selFg`, рамки — `frameA`, ссылки и заголовки — `titleA`/`head`, состояния — `ok`/`warn`/`err`); своих
  расчётов цветов и контраста в консоли нет. Нет брендинга — тема IT TASK из `design/tokens.toml`, как сейчас.
- Страница входа: `GET /api/v1/public/branding` — сначала без `domain`, затем по домену из введённого имени входа
  (после `@`, с задержкой); знак и название вместо IT TASK (`null` — встроенные), `document.title` — название
  продукта. После входа — `effective` своей организации (администратор установки — уровня установки); знак и
  название в шапке.
- Раздел «Брендинг»: уровень установки (администратору установки) и вкладка организации — все поля необязательны:
  название, основной цвет и таблица ролей по темам (светлая, тёмная) и CLI — у каждой роли `ColorPicker` antd с вводом
  `#RRGGBB` и «как на уровне выше»; рядом — действующий цвет роли из `effective` (выведенный из основного или с уровня
  выше). Загрузка знака (`Upload`, только PNG, проверка размера до отправки), предпросмотр шапки, выделения и
  F-клавиш в обеих темах, сброс с подтверждением. Ошибки 422 — у поля роли из `errors` (роль, пара, тема) с текстом
  `detail` сервера.
- Нет знака или он не загрузился — только название.

## Приёмка
- Тесты: тема строится из ответа сервера, без брендинга — из токенов; страница входа перезапрашивает брендинг по
  домену; незаданная роль показывает действующий цвет уровня выше; форма показывает ошибку контраста у поля роли из
  `errors`; сброс возвращает тему установки.
- Ручная проверка на стенде: свой брендинг установки и организации — вход, шапка, светлая и тёмная темы; организация
  меняет только название — цвета и знак установки остаются.
