## Сделать
- Класс B: схема Admin API меняется — копия консоли `console/src/api/openapi.json` и `schema.d.ts`
  (`thepost admin openapi -o …`, затем `npm run gen:api`) в этом же PR, иначе сверка схемы в CI падает; зависимость
  `image` (только `png`, с `Limits`; та же версия, что у `tp-tui` после DEPS-17, #794) — версией, что уже в
  `Cargo.lock`; новых крейтов нет. Цвета, вывод ролей и контраст — только из контракта (`tp_contracts::branding`),
  своих расчётов и второго списка цветов нет.
- Уровень установки — `GET|PUT|DELETE /api/v1/branding` (администратор установки), знак — `PUT|DELETE
  /api/v1/branding/logo`. Уровень организации — `GET|PUT|DELETE /api/v1/orgs/{org}/branding` и `PUT|DELETE
  /api/v1/orgs/{org}/branding/logo` (администратор организации и установки; `GET` — и оператор). `PUT` — тело
  `Branding` без знака: `{product_name?, primary?, light?, dark?, cli?}` — все поля необязательны, роли — имена из
  `design/tokens.toml` (знак сохраняется); `GET` — `{own, effective}`: свой набор уровня и `EffectiveBranding`
  (`BrandingLevels::effective`: название, знак, все роли обеих тем и CLI); `DELETE` — сброс уровня. Каждое изменение и
  сброс — в журнал аудита (уровень, старые и новые значения, у знака — хэш, без байтов).
- Знак — тело `image/png` (иной тип — 415), больше 256 КБ — 413; не PNG, битый файл, больше 1024×1024 — 422. PNG
  проверяется полным разбором `image` с `Limits`; байты — `BlobStore::put_raw(BrandLogo::path())` (уже есть — не
  писать). Знак ставится и без названия и цветов уровня (остальное — с уровня выше). Прежний знак после замены или
  сброса удаляется (`delete_raw`), если `logo_in_use` — `false`.
- Контраст при `PUT` (решение 122): действующий набор уровня — `BrandingLevels::effective` (организация — поверх
  текущего набора установки, установка — поверх IT TASK) — проверяется `Palette::contrast_issues`: каждая пара
  `[[contrast]]` обеих тем (текст — 4,5:1, рамки и заливки — 3:1) и роли CLI на обоих фонах терминала (3:1), без
  исключений. Заданные роли не сдвигаются; незаданные роли уровня с основным цветом выводит контракт
  (`Branding::palette_over`). Не проходит — 422 problem+json: `detail` по-русски и `errors: [{field, theme, role, bg,
  contrast, min}]` («светлая тема: выделение sel #F5E663 на панели panel #FFFFFF — 1,3:1, нужно 3:1»). Формат цвета
  или неизвестная роль — 400. Проверка — чистые функции контракта: уровень организации — `BrandingLevels::contrast_issues`
  (поверх текущего набора установки), уровень установки — `installation_change_issues(новый набор,
  org_brandings())`: изменение установки отклоняется 422 problem+json, если ломает действующую палитру хотя бы одной
  организации, — `errors` со списком организаций и пар (`org`, `theme`, `role`, `bg`, `contrast`, `min`; `org` = `null`
  — сам набор установки).
- Страховка отрисовки (данные из старой версии): `GET` и открытый маршрут отдают `BrandingLevels::effective` — пара,
  не прошедшая проверку, берётся с уровня выше (`Branding::safe_palette_over`), а не показывается нечитаемой.
- Открытый маршрут без входа — `GET /api/v1/public/branding?domain=<домен>` и
  `GET /api/v1/public/branding/logo/{hash}`: только название (`null` — встроенное), цвета всех ролей и ссылка на знак
  (`null` — встроенный IT TASK), без имени, идентификатора и уровня организации. Организация — по принятому домену
  (`TransportStore::cluster`); неизвестный домен, организация без своего набора и запрос без `domain` — один и тот же
  ответ (брендинг установки). `ETag`, `Cache-Control: public, max-age=300`; знак по хэшу — `immutable`. Защита от
  перебора — общее ограничение частоты Admin API по адресу клиента.
- Все операции — в `openapi_spec()` (их подхватят консоль, CLI и текстовый интерфейс, CI-16). CLI —
  `thepost admin branding show|set [--name] [--primary] [--role <тема>.<роль>=#RRGGBB]…|reset|logo set <файл.png>|logo
  reset [--org <орг>]`; `tp-admin-client` — `public_branding(domain)` и `branding_logo(hash)` для экрана входа
  текстового интерфейса (TUI-08).

## Приёмка
- Тесты: без наборов — палитра IT TASK (`Palette::it_task`, выделение `#E3107F`); набор только с основным `#177CAA`
  проходит обе темы и CLI; `light.sel` = `#F5E663` — 422 с `errors` (роль `sel` на `panel`, светлая тема); `#FFF` — 400;
  организация задала только название — название её, знак и цвета установки;
  знак: JPEG — 415, 300 КБ — 413, 2048×16 — 422, годный PNG — 200 и запись аудита; знак без названия и цветов — 200.
- Установка с тёмной панелью, под которой не читается свой текст организации, — 422 с `errors` по этой организации;
  тот же набор без организаций — 200. Набор, сохранённый в обход проверки, в `effective` отдаётся без нарушений.
- Права: администратор организации не меняет уровень установки и чужую организацию (403/404); оператор — только `GET`.
- Открытый маршрут: ответы для неизвестного домена, домена организации без своего набора и без `domain` побайтно
  равны; домен организации со своим набором — её значения поверх установки; в ответе нет полей организации;
  `If-None-Match` — 304.
- Сброс организации возвращает брендинг установки; знак, не нужный больше ни одному уровню, удалён из BLOB.
