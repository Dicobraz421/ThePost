## О документе

ThePost управляется тремя способами: командной строкой `thepost`, веб-консолью администратора и текстовой консолью `thepost admin tui`. Все три работают через один и тот же Admin API узла, поэтому права, проверки и записи в журнал аудита у них одинаковые. Выбирайте интерфейс по задаче, а не по возможностям.

| Интерфейс | Когда удобен | Где работает |
| --- | --- | --- |
| `thepost` (узел) | установка, запуск, проверка конфигурации и хранилища | на сервере, от пользователя `thepost` |
| `thepost admin` | учётные записи, политики, очередь — из скриптов и вручную | на сервере или на рабочем месте с доступом к Admin API |
| Веб-консоль | повседневное администрирование мышью | браузер |
| `thepost admin tui` | то же, что консоль, но в терминале по SSH | терминал |

Документ описывает версию 0.2.0. Справочник собран по коду ветки `main` на 14.11.2026; то, что ещё в открытых PR, помечено отдельно.

## Начало работы

Первого администратора заводит `thepost admin init` на самом сервере, дальше все интерфейсы входят по паролю или через OIDC и работают с сессией `tps_…`.

### Первый администратор

1. На сервере от root или от учётной записи службы: `sudo thepost admin init --email admin@example.ru --name "Администратор"`. Узел должен быть запущен с ролью `admin`: команда идёт через локальный сокет.
2. Команда заводит учётную запись и принятый домен и один раз показывает пароль и токен `tpa_…` (живёт `admin.init.token_ttl`, по умолчанию 10 мин). Сохраните пароль сразу.
3. Повторный запуск даёт отказ `409`; перевыпуск — `--force`, он пишется в журнал аудита.

Токен `tpa_…` CLI не принимает: он нужен только для первого входа в веб-консоль, когда вход по паролю выключен. В CLI входите по паролю из шага 2.

### Вход и сессия

```sh
thepost admin login --user admin@example.ru      # пароль спросит без эха; выдаст tps_…
export THEPOST_ADMIN_TOKEN=tps_…
thepost admin whoami
```

| Токен | Откуда | Срок | Где принимается |
| --- | --- | --- | --- |
| `tpa_…` | `thepost admin init` | 10 мин, один раз | только первый вход в веб-консоль |
| `tps_…` | `thepost admin login --user` или вход в консоль | 8 ч | CLI, TUI, веб-консоль |
| токен OIDC | `thepost admin login --oidc` (вход с устройства, RFC 8628) | по поставщику | CLI, TUI |

- В сценариях пароль передаётся первой строкой stdin: `--password-stdin`. Аргументом пароль не передаётся.
- `--oidc` требует `auth.oidc` и `cli.oidc.client_id` в `config.yaml`; адрес и код печатаются в stderr, токен — в stdout: `export THEPOST_ADMIN_TOKEN="$(thepost admin login --oidc)"`.
- Отказы входа: `401` — неверный пароль или временная блокировка после неудачных попыток; `403` — у учётной записи нет ролей `admin.roles`; `404` — вход по паролю выключен (`admin.password_login`).
- Выхода (`logout`) и списка сессий в CLI нет: сессия истекает сама через 8 ч.

### Общие ключи `thepost admin`

Ставятся в любом месте строки; у большинства есть переменная окружения.

| Ключ | Переменная | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `--url <адрес>` | `THEPOST_ADMIN_URL` | `http.admin.listen` из `config.yaml` | адрес Admin API (`https://`, при `allow_plaintext` — `http://`) |
| `--token <токен>` | `THEPOST_ADMIN_TOKEN` | — | сессия `tps_…` или токен OIDC; ключ виден в списке процессов — лучше переменная |
| `--org <UUID>` | `THEPOST_ADMIN_ORG` | организация администратора | организация запросов |
| `--json` | — | выкл. | ответ Admin API в JSON вместо таблицы |
| `--ca-file <PEM>` | — | — | корневые сертификаты для TLS Admin API |
| `--insecure` | — | выкл. | не проверять сертификат (как `curl -k`), только для loopback |
| `--timeout <сек>` | — | 30 | предельное время запроса |
| `-c, --config <путь>` | `THEPOST_CONFIG` | `/etc/thepost/config.yaml` | откуда брать адрес и настройки OIDC |
| `--color auto\|always\|never` | `NO_COLOR`, `CLICOLOR_FORCE` | `auto` | цвет вывода; **появится с PR #791** |

Учётная запись в аргументах — UUID или имя входа (без учёта регистра), группа — UUID, имя или адрес, домен — UUID или имя.

## Справочник: команды узла `thepost`

Команды узла выполняются на сервере и читают `config.yaml`: путь — `-c, --config`, затем `THEPOST_CONFIG`, затем `/etc/thepost/config.yaml`. Отдельной команды `migrate` нет: миграции базы применяются при запуске узла (`meta.migrate_on_start`).

| Команда | Назначение | Ключи | Код выхода | Пример |
| --- | --- | --- | --- | --- |
| `thepost serve` | запуск узла с ролями из `config.yaml`, работает до SIGTERM | — | 0 — штатная остановка; 1 — не запустился или роль упала | `thepost serve -c /etc/thepost/config.yaml` |
| `thepost config check` | строгая проверка: неизвестный или неверный параметр — ошибка; при успехе список ссылок на секреты | — | 0 — верна; 1 — ошибки | `thepost config check -c deploy/config/all.yaml` |
| `thepost config schema` | JSON Schema `config.yaml` для редакторов | — | 0 / 1 | `thepost config schema > schema.json` |
| `thepost doctor` | проверка окружения: секреты, СУБД, BLOB, часы, песочница процесса, DNS домена (MX, SPF, DKIM, DMARC, MTA-STS, PTR, SRV), сертификаты, PKI, приёмники аудита | `--json` | 1 — есть проверка `fail` | `sudo -u thepost thepost doctor` |
| `thepost verify` | сверка хранилища писем с учётом объектов в обе стороны | `--fix` — удалить «сирот» и пометить повреждённые; `--json` | 0 — расхождений нет; 1 — есть | `thepost verify --json` |
| `thepost admin init` | первый администратор и принятый домен через локальный сокет | `--email`, `--name`, `--force`, `--socket` | 0 / 1 | `sudo thepost admin init --email admin@example.ru` |
| `thepost admin openapi` | схема Admin API (OpenAPI, JSON), узел и токен не нужны | `-o, --output <файл>` | 0 / 1 | `thepost admin openapi -o openapi.json` |
| `thepost admin tui` | текстовая консоль администратора (раздел «Текстовая консоль») | ключи подключения `thepost admin` | 0 / 1 | `thepost admin --insecure tui` |

Служебная скрытая команда `thepost search-extract` — подпроцесс индексатора для вложений, вручную не вызывается.

## Справочник: команды `thepost admin`

Синтаксис: `thepost admin [общие ключи] <ресурс> <действие> <аргументы> [ключи]`. 43 команды в 12 группах; все изменения пишутся в журнал аудита.

### Вход — `login`, `whoami`

| Команда | Что делает | Ключи |
| --- | --- | --- |
| `login --user <адрес>` | вход по паролю, выдаёт `tps_…` | `--password-stdin` |
| `login --oidc` | вход у поставщика OIDC с устройства | — |
| `whoami` | текущий администратор, организация, роли | — |

### Учётные записи — `account`

| Команда | Что делает | Ключи |
| --- | --- | --- |
| `account create <вход>` | новая учётная запись в принятом домене; пароль для почты — отдельно, `app-password create` | `--name <имя>` |
| `account list` | список по имени входа, страницы проходит сам | `--login`, `--prefix`, `--after <вход>`, `--limit N` |
| `account get <учётка>` | карточка: псевдонимы, домен, занято, квота, скрытие из книги «Организация» | — |
| `account block <учётка>` | запрет входа; сеансы IMAP и POP3 закрываются сразу | — |
| `account unblock <учётка>` | снятие блокировки входа | — |
| `account rename <учётка> <имя>` | новое отображаемое имя | — |
| `account set <учётка>` | псевдонимы и скрытие из книги | `--alias <адрес>` (повторяется, заменяет список), `--no-aliases`, `--hidden-from-gal true\|false` |

У записей из каталога (LDAP) `block`, `rename` и `set` отвечают `409`: правьте их в каталоге.

### Пароли приложений — `app-password`

| Команда | Что делает | Ключи |
| --- | --- | --- |
| `app-password create <учётка>` | пароль для IMAP, SMTP, JMAP; значение показывается один раз | `--label <подпись>` |
| `app-password list <учётка>` | пароли без значений, в том числе отозванные | — |
| `app-password revoke <учётка> <id>` | отзыв одного пароля | — |

### Политики — `policy`

Уровень: без ключей — организация, `--domain <домен>` или `--account <учётка>`. Наследование: организация → домен → ящик.

| Команда | Что делает |
| --- | --- |
| `policy get` | заданное на уровне и действующее с учётом вышестоящих |
| `policy set --file <путь\|->` | замена политики уровня целиком из JSON; поля, которых нет в файле, на уровне не заданы |

Поля JSON: `quota_bytes`, `trash_retention`, `retention`, `send_per_hour`, `rcpts_per_hour`, `max_recipients`, `dkim_selector`, `milter_profile`, `trash_purge`, `archive_after`, `archive_quota_bytes`. Без политики: 1000 писем и 2000 адресатов в час, 100 получателей в письме.

```sh
echo '{"send_per_hour": 500, "quota_bytes": 10737418240}' | thepost admin policy set --file - --domain example.ru
```

### Правила Sieve — `sieve`

| Команда | Что делает |
| --- | --- |
| `sieve list <учётка>` | скрипты, размер, активный |
| `sieve get <учётка> <имя>` | текст скрипта в stdout |
| `sieve put <учётка> <имя> --file <путь\|->` | создать или заменить; текст проверяет узел, ошибки — «строка N, столбец M» |

| Команда | Что делает | Ключи |
| --- | --- | --- |
| `vacation get <учётка>` | состояние, срок, тема, текст | — |
| `vacation set <учётка>` | включить или изменить; незаданное остаётся | `--off`, `--from`, `--to` (RFC 3339 или `-`), `--subject`, `--text` / `--text-file`, `--html-file` |

| Команда | Что делает | Ключи |
| --- | --- | --- |
| `trash list <учётка>` | письма корзины, новые первыми, и срок хранения | `--hidden`, `--subject` (тема и отправитель, запрос пишется в аудит), `--offset`, `--limit` |
| `trash restore <учётка> <письмо>` | восстановить в исходную папку (нет — во «Входящие») | `--hidden` |

### Журналы — `audit`, `delivery`

| Команда | Что делает | Ключи |
| --- | --- | --- |
| `audit search` | действия администраторов; нужно хотя бы одно условие | `--since`, `--until`, `--actor`, `--method`, `--route`, `--limit`, `--after <номер>` |
| `delivery search` | события доставки: отправитель, получатели, решение, причина | `--sender`, `--recipient`, `--message-id`, `--since`, `--until`, `--limit`, `--after` |

Время — RFC 3339, например `2026-12-01T00:00:00Z`.

### Транспорт — `transport`

Запись идёт по версии снимка: если кто-то изменил настройки раньше, придёт `409` — повторите команду.

| Команда | Что делает | Ключи |
| --- | --- | --- |
| `transport domain list` / `create <имя>` / `delete <домен>` | принятые домены | `--relay host[:port]` — пересылка на внутренний узел |
| `transport source list` / `set <имя>` / `delete <имя>` | доверенные источники (шлюзы и приложения без входа) | `--network <CIDR>` или `--client-cert <dNSName>`; `--xclient`, `--authserv-id`; или `--application`, `--sender`, `--external` |
| `transport route list` / `set <шаблон>` / `delete <шаблон>` | политики доменов назначения (`example.org`, `*.example.org`, `*`) | `--tls opportunistic\|required`, `--pin <SHA256>`, `--smart-host`, `--egress-ip` |

### Чего нет в CLI

Почтовые контакты, очередь исходящей почты, снятие блокировки по перебору паролей, сессии и `logout`, подразделения, отключённые ящики, модерация групп. Часть из них есть в веб-консоли и в текстовой консоли (F9 — все операции Admin API).

## Веб-консоль администратора

Консоль открывается по адресу `https://<узел>:8443/console/` — её раздаёт сам узел с ролью `admin` на слушателе Admin API (`http.admin.listen`, по умолчанию `127.0.0.1:8443`). Этот адрес бывает только внутренним: снаружи консоль открывают через VPN или обратный прокси, на публичном 443 её нет.

### Вход

1. Откройте `https://<узел>:8443/console/`. Сертификат должен подходить к имени в адресе; на стенде импортируйте CA стенда.
2. Выберите способ входа — консоль показывает только включённые:
   - **имя входа и пароль** (пароль каталога, пароль приложения или выданный `admin init`); включён, если не настроен `admin.oidc`, иначе — по `admin.password_login`;
   - **«Войти через OIDC»** — если настроены `auth.oidc` и `admin.oidc`;
   - **токен администратора** `tpa_…` — только при выключенном входе по паролю.
3. Сессия живёт 8 ч в этой вкладке браузера. После истечения или перезапуска узла консоль вернёт на экран входа. Выход — пункт «Выход» в меню.

Вход по паролю защищён от перебора: после серии ошибок даже верный пароль отвергается до конца `auth.abuse.block_for`.

### Роли

Роли назначаются только в `config.yaml` (`admin.roles`: роль, имена входа, группы). Без роли войти нельзя (`403`).

| Роль | Что видит | Что может |
| --- | --- | --- |
| `installation_admin` | все разделы, выбор организации в шапке, вкладка «Транспорт → Инсталляция» | всё |
| `organization_admin` | все разделы своей организации | менять свою организацию |
| `operator` | всё, кроме журнала аудита и аудита ящиков | только читать |
| `auditor` | «Журнал аудита» и «Аудит ящиков» | только читать |

Раздел, недоступный роли, по прямому адресу показывает «Нет доступа».

### Разделы меню

| Раздел | Что там | Действия |
| --- | --- | --- |
| Организация | политика организации (квоты, сроки, лимиты отправки, DKIM, Milter) с действующим значением у каждого поля; общий доступ к календарям | изменить политику; подтвердить массовое отключение из каталога |
| Учётные записи | вход, имя, источник, состояние, объём; поиск по началу имени | создать; в карточке — имя, «Разрешить вход», псевдонимы, скрытие из книги, политика ящика, списки отправителей, аудит ящика, представители, общий доступ, пароли приложений; ссылки на корзину и правила |
| Ресурсы | переговорные и оборудование | создать, правила бронирования, ответственные, удалить |
| Отключённые ящики | записи, отключённые каталогом, и срок хранения | восстановить; подключить к другой учётной записи |
| Группы рассылки | имя, адрес, метки «каталог», «модерация», «скрыта» | создать, участники, «Кто может писать», модераторы, динамический состав, удалить |
| Адресная книга | внешние контакты организации | создать, изменить, удалить |
| Оргструктура | дерево подразделений и сотрудники | создать, изменить, удалить |
| Модерация | очередь писем на одобрение | одобрить, отклонить с причиной; тема — по переключателю, запись в аудит |
| Очередь | исходящая почта: получатели, попытки, последняя ошибка, состояние | фильтр по состоянию и адресу; «Повторить» |
| Правила организации | скрипт Sieve для входящей почты всех ящиков | править (ошибки — со строкой и столбцом), удалить |
| Транспорт | вкладки «Принятые домены», «Доверенные источники», «Маршруты», «Инсталляция» | добавить, изменить, удалить; «Политика» домена |
| Журнал доставки | события с решением и причиной | фильтры; по Message-ID — лента событий письма |
| Журнал аудита | действия администраторов | фильтры по администратору, методу, маршруту, интервалу |
| Аудит ящиков | доступ к чужим ящикам | фильтры; политика аудита организации |

С карточки учётной записи открываются «Корзина» (вкладки «Корзина» и «Скрытые», кнопка «Восстановить») и «Правила и автоответ» (скрипты Sieve пользователя и автоответ с периодом, темой, текстом).

### Общее поведение

- В шапке — текущая организация (у администратора инсталляции — список для смены) и имя входа.
- Результат действия — всплывающее сообщение: «Создано», «Сохранено», «Ошибка (код N)».
- Листание: в «Учётных записях» и «Очереди» — «Показать ещё», в журналах — «Назад» / «Дальше».
- Если настройки транспорта успел изменить другой администратор, узел отвечает `409`, и списки перечитываются.
- Язык — только русский, тема — светлая; фирменный стиль (UI-19) ещё не подключён.
- Консоль выключается в `config.yaml`: `admin.console.enabled: false`. Консоль на отдельном веб-сервере — архив `console/dist`, рядом `config.json` с `apiBase`, на узле — `admin.console.cors_origins`.

## Текстовая консоль `thepost admin tui`

Текстовая консоль — двухпанельный интерфейс в стиле Midnight Commander для терминала по SSH. Экраны строятся по схеме Admin API, поэтому через F9 доступна любая операция API, даже если для неё нет отдельного раздела.

### Запуск и вход

```sh
thepost admin tui --url https://127.0.0.1:8443 --ca-file /etc/thepost/pki/ca.pem
```

- Ключи: `--url`, `--token`, `--ca-file`, `--insecure`, `--timeout`. Адрес — `--url` или `THEPOST_ADMIN_URL`; из `config.yaml` подкоманда его не берёт, иначе впишите в форму входа.
- Есть `THEPOST_ADMIN_TOKEN` или `--token` — вход сразу. Нет — форма: адрес, способ (‹ пароль / токен ›, переключается ←→), имя входа, пароль. Поля — ↑↓ или Tab, вход — Enter.
- Нужен терминал не меньше 80×24. `NO_COLOR` включает монохромный режим с выделением инверсией.
- Выход — F10 или Ctrl+C.

### Экран

| Место | Что там |
| --- | --- |
| верхняя строка | меню «Установка · Организация · Вид · Сервис · Справка» и версия |
| левая панель «Ресурсы» | разделы организации, другие организации (Enter — перейти), «Конфигурация узла» |
| правая панель | список, карточка или форма; активная панель — с двойной рамкой |
| под панелями | подробности выделенной записи |
| строка состояния | знаки ● норма, ▲ внимание, × ошибка |
| строка команды | та же операция командой `thepost admin …` или «нет в CLI: МЕТОД путь» |
| нижняя строка | подписи F-клавиш |

Строка команды помогает перенести ручное действие в скрипт.

### Клавиши

| Клавиша | Действие |
| --- | --- |
| Tab / Shift+Tab | другая панель |
| ↑↓ PgUp PgDn Home End | по строкам; ↓ в конце списка подгружает следующую страницу |
| Enter, F3 | открыть раздел или запись |
| Esc, Backspace, ← | назад |
| F1 | справка по операции |
| F2 | фильтр списка или перечитать |
| F4 | правка записи |
| F5, F6 | действия раздела (см. таблицу разделов) |
| F7 | создать |
| F8 | удалить: подтвердить Enter / y / д, отменить Esc / n / н |
| F9 | меню всех операций Admin API |
| F10, Ctrl+C | выход |

В формах: ↑↓ или Tab — поле, ←→ — выбор варианта, Enter — выполнить, Esc — отмена. Ошибка узла показывается у поля. Где операции нужен ящик, консоль спрашивает имя входа, а не UUID.

### Разделы

| Раздел | Столбцы и свои клавиши |
| --- | --- |
| Учётные записи | Адрес / Имя / Квота / С (× заблокирована, ▲ квота ≥ 90 %). F5 — включить или запретить вход; F6 — пароли приложений (F7 выпуск, F8 отзыв); F8 — скрыть из книги; F4 — имя и псевдонимы; F7 — создать |
| Домены | F7 создать, F4 правка, F8 удалить |
| Группы | Имя / Адрес / Уч. / С (▲ модерируемая). Enter — состав: F7 добавить по имени входа, F8 убрать |
| Контакты, Оргструктура, Ресурсы | общие клавиши: F7, F4, F8 |
| Политики | Параметр / Задано / Действует. F4 — политика организации; F5 — домены → домен → F3 → F4; F6 — ящик по имени входа → F4 |
| Журналы | аудит: Время / Администратор / Метод / Код; F5 — переключить на журнал доставки и обратно; F2 — фильтр |
| Модерация | F5 одобрить, F8 отклонить |
| Корзина | спрашивает имя входа; F5 восстановить, F6 скрытые |
| Очередь | список и F2 фильтр; повтор доставки — F9 → `retry_queue` |
| Конфигурация узла | пока только поясняет, где править `config.yaml` (ниже) |

Транспортных источников, маршрутов, Sieve, автоответа, аудита ящиков и отключённых ящиков в дереве нет — они доступны через F9.

### Конфигурация узла

Раздел умеет показывать секции `config.yaml` с описаниями и умолчаниями, править значения (F4), проверять их `thepost config check` до записи и сохранять копию `config.yaml.bak`. Файл с меткой `# thepost: managed-by=ansible|helm` открывается только для чтения.

**В версии 0.2.0 раздел ещё не подключён к узлу**: он только поясняет, что `config.yaml` правят на самом узле, а проверяют `thepost config check`. Подключение делается отдельной доработкой.

## Типовые задачи

Одна и та же задача в трёх интерфейсах; прочерк — интерфейс этого пока не умеет.

| Задача | CLI | Веб-консоль | Текстовая консоль |
| --- | --- | --- | --- |
| Завести домен | `transport domain create example.ru` | Транспорт → Принятые домены → «Добавить» | Домены → F7 |
| Завести пользователя | `account create ivanov@example.ru --name "Иван Иванов"` | Учётные записи → «Создать» | Учётные записи → F7 |
| Выдать пароль для почтовой программы | `app-password create ivanov@example.ru --label Thunderbird` | карточка → «Пароли приложений» → «Выпустить пароль» | выделить → F6 → F7 |
| Создать группу | `group create "Продажи" --address sales@example.ru --account a@example.ru` | Группы рассылки → «Создать» | Группы → F7; состав — Enter → F7 |
| Задать лимиты и квоту | `policy set --file policy.json [--domain …\|--account …]` | Организация, «Политика» домена или карточка ящика | Политики → F4 / F5 / F6 |
| Заблокировать и разблокировать вход | `account block` / `account unblock` | карточка → «Разрешить вход» | выделить → F5 |
| Восстановить письмо из корзины | `trash list` → `trash restore <учётка> <письмо>` | карточка → «Корзина» → «Восстановить» | Корзина → имя входа → F5 |
| Найти, что стало с письмом | `delivery search --message-id <id>` | Журнал доставки → фильтр → нажать Message-ID | Журналы → F5 → F2 |
| Повторить доставку из очереди | — | Очередь → фильтр → «Повторить» | Очередь → F2; повтор — F9 → `retry_queue` |
| Кто и что менял | `audit search --since 2026-12-01T00:00:00Z` | Журнал аудита → фильтры | Журналы → F2 |
| Включить автоответ | `vacation set <учётка> --to … --text "…"` | карточка → «Правила и автоответ» → «Автоответ» | F9 |

### Первый пользователь от начала до конца (CLI)

```sh
sudo thepost admin init --email admin@example.ru
thepost admin login --user admin@example.ru
export THEPOST_ADMIN_TOKEN=tps_…
thepost admin account create ivanov@example.ru --name "Иван Иванов"
thepost admin app-password create ivanov@example.ru --label Thunderbird
```

Пароль из последней команды показывается один раз — передайте его пользователю. В почтовой программе: логин — адрес целиком, IMAP 993 (SSL/TLS), отправка 465 (SSL/TLS) или 587 (STARTTLS).

### Пользователь не может войти

1. `thepost admin account get <адрес>` — если вход запрещён, `account unblock`.
2. `thepost admin app-password list <адрес>` — не отозван ли пароль; при нужде выпустите новый.
3. После серии неверных паролей срабатывает защита от перебора: блокировка снимается сама по истечении `auth.abuse.block_for`. Снять её раньше ни один интерфейс пока не умеет.

## Приложение

### Переменные окружения

| Переменная | Где | Значение |
| --- | --- | --- |
| `THEPOST_CONFIG` | все команды | путь к `config.yaml` |
| `THEPOST_ADMIN_URL` | `thepost admin`, `tui` | адрес Admin API |
| `THEPOST_ADMIN_TOKEN` | `thepost admin`, `tui` | сессия `tps_…` или токен OIDC |
| `THEPOST_ADMIN_ORG` | `thepost admin` | UUID организации |
| `NO_COLOR` | `tui`; CLI — с PR #791 | без цвета |
| `CLICOLOR_FORCE`, `COLORTERM` | CLI — с PR #791 | цвет в конвейере; фирменные цвета при `truecolor` |

Пустое значение переменной считается отсутствующим.

### Коды выхода

| Код | Значение |
| --- | --- |
| 0 | успех |
| 1 | ошибка или отказ Admin API; `doctor` — есть проверка `fail`; `verify` — есть расхождения; `serve` — узел не стартовал |
| 2 | неверные аргументы командной строки |

### Сообщения об ошибках

Данные идут в stdout, ошибки и подсказки — в stderr. Отказ Admin API выглядит так:

```
thepost: admin: <МЕТОД> <ПУТЬ>: <код> <title>: <detail> (<подсказка>)
```

С PR #791 формат меняется на две строки: «ошибка: …» и «подсказка: …» с командой, которая поможет (например, `thepost admin account get <адрес>` при `409`). Ошибки в тексте Sieve выводятся строками «строка N, столбец M: …».

| Код | Чаще всего означает |
| --- | --- |
| 401 | сессия истекла — снова `thepost admin login` |
| 403 | нет роли в `admin.roles` или не хватает прав роли |
| 404 | записи нет или вход по паролю выключен |
| 409 | адрес занят, запись из каталога (правится в LDAP) или настройки транспорта уже изменены — повторите |
| 422 | неверные данные: например, ошибка в скрипте Sieve со строкой и столбцом |

### Ограничения версии 0.2.0

- Один сервер: многоузловой режим, шарды и S3 — в следующих версиях.
- Admin API и веб-консоль слушают только внутренний адрес; роли администраторов задаются только в `config.yaml`.
- Удалить учётную запись нельзя ни в одном интерфейсе.
- `account block` сразу закрывает сеансы IMAP и POP3; сеансы ManageSieve и отправки живут до разрыва.
- Списки отправителей и динамические группы хранятся, но при доставке пока не применяются.
- Веб-консоль: только русский язык и светлая тема, без импорта из CSV.
- Текстовая консоль: нет входа через OIDC, мыши и фирменной темы; «Конфигурация узла» не подключена; адрес из `config.yaml` не подставляется.
- Перехода с бет `beta-*` нет: только новая установка.
